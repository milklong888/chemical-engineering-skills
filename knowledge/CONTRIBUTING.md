# 知识贡献与读取准则

知识增补的目标是解决实际问题，不是增加条目数量。已有结论、条件和边界已经被覆盖时，重复候选应跳过；来源仍有疑点但可能有用时应保留待核，不能把来源疑点当作无价值。

## 怎样读取

先按问题边界和来源资格定位最高充分层次，再取足以回答问题的完整知识块及其条件；仍缺机制、计算或证据时，才按精确 `related_node_ids` 下钻。分层不表示泛原则可以替代直接答案。结果用于解释、筛选和组织下一步工作，不自动成为项目参数、软件运行结果或工程验收结论。

查询可能截断长正文；需要完整释义时使用 `--node-id <ID> --full-text`，不要依据片段补猜。`--vector` 使用随包的 768 维确定性 n-gram 哈希向量，不是学习式语义模型，也不提高来源权威。日常入口见[知识总览](README.md)。

问题已有明确范围时可先指定 `--corpus`：基础原理用 `chemical_principles`，V10 操作细节用 `aspen_v10`，对应通用方法用 `sun_lanyi`。词项统计和结果均按该范围处理；需要其他来源时再跨库检索。一次分库未命中不表示全库没有相关知识。

## 什么值得入库

每个候选先说明实际用途，再给出读者能够无歧义复述的完整释义：结论、必要条件、适用边界和禁止迁移的部分应在同一块中闭合。不要求逐符号拆分、固定条数或长篇教程。提交至少包含：

- 新写的释义正文，而不是目录、阅读日志、整页摘录或旧界面按钮步骤；
- 来源编号、文件 SHA256、精确物理页/图表锚，以及必要的单位和基准；
- 适用范围、开放疑点和不可直接迁移的参数或配置；
- 与现有节点的精确 ID 对比，说明结论、条件或边界的新增差异。

先读完整候选及条件，再按精确 ID 回读已有支持节点；检索不足时继续取证，不用关键词命中或向量相似度代替语义去重。无实际用途的内容跳过；有用的新条件或反例不应仅因题名相似而丢弃。

原件可在有合法依据的私有核验环境中保存。公开贡献只提交新的通用释义、来源身份和可追溯页锚，不公开原始 PDF、整页转写、私人资料或项目机密。

## 怎样提交和审核

资料来源知识与任务经验分开处理。直接来源候选保留 `X` 证据、来源身份、许可范围和页锚；任务经验还要有独立谱系和候选质量审查。

贡献者可先提交候选 PR，注明用途、已有覆盖和未解决项。进入正式知识前，由独立 reviewer 回读正文与来源，并绑定完整批次。不要手改 `records.jsonl`、向量或索引，也不要把 `approved=true` 当作审查完成；未审候选不进入默认检索和向量库。

字段、构建及校验流程见[维护说明](MAINTENANCE.md)；已有批次范围见[新增知识说明](intake/README.md)。构建出的候选仍是待采纳版本，正式发布、安装和工程验收分别决定。
