# 常识 RAG 的读取与泛化

在化工专家需要解释“为什么合理、怎样选择方法、哪里可能违反常识”时使用。
知识正文、来源身份、准入状态和离线索引由本产品一并提供，以
`knowledge/manifest.json` 为准。日常查询不连接另一个资料仓库。

## 先定位判断层，再取证

| 抽象层 | 专家要回答的问题 | 进入下一层的理由 |
| --- | --- | --- |
| L3 思想/系统观 | 边界、守恒、平衡/速率、尺度、耦合、能量品位、可实现性、权衡 | 需要确定控制机制 |
| L2 原理/机制 | 为什么有效、何种相态/推动力/限制控制它 | 需要确定方法及所需输入 |
| L1 方法/模型 | 怎样计算/筛选、假设/单位/适用域是什么 | 需要公式、数值或逐页证明 |
| L0 来源细节 | 原文、公式、表、曲线、上下标、页码和证据状态 | 供核对、计算或冲突诊断 |

上层必须能下钻，细节不能代替设计目的和系统权衡。设备选型程序是实施与反馈
能力，不是一个更高事实权威；使用 `PROCESS_EQUIPMENT_FEEDBACK.md` 将其结果
反馈到流程合理性判断。

## 来源轴与抽象轴分别保存

来源组织轴采用：

`subject_root → source_volume → chapter/support_unit → coarse_KU → evidence`

它说明内容来自哪里；`knowledge_layer=L3/L2/L1/L0` 说明能解决哪一层问题。
同一章节可支撑多个抽象层，同一 L3 思想可跨章节/来源得到支持，不按目录深度
直接转换 L3/L2/L1。书名是来源卷，不应与化工原理、反应工程等学科主题混成
一层。设备算法仍属设备能力域，不能被包装为教材来源。

## 以实际用途、语义去重和复述门决定准入

1. 先写明知识块的实际用途：它要支撑哪种概念/适用域解释、计算、选型或排错；
   只有目录、术语或阅读记录而无可回答用途的内容 `skip`。
2. 按结论、适用条件和边界做语义去重，不按字符串或段落切分。已有结论由现有
   node 承载；重复候选引用该 node 并 `skip`。只有新增条件、排除边界或可验证
   推导使结论实际不同，才作为新增。
3. 内容准入门是：读者不看原文也能无歧义复述这块讲什么及其必要条件/结论；仅在
   省略会造成误解时补充边界，不强制统一栏目。若仍有多种合理解释，回到来源
   核对或保留候选，不放行。
4. 来源页账本完整保留；原始数字化覆盖、可回答内容、正式检索激活是不同状态。
5. 直接回答块、关联支持、证据留档、关系、前后置页、无价值内容分别处理。
   支持内容可沿关系展开，不能因包含关键词就独立充当答案。
6. 公式、完整表体、续表、曲线族、流程拓扑及上下文是逻辑对象；按固定字符
   切出的片段不能自动取得正式准入。符号、表格单元、曲线点留在证据数据层，
   不为数量指标拆成独立 KG 节点。
7. `retrieval_eligible` 与 `embedding_eligible` 是显式状态；缺字段、待核内容
   和受保护未批准内容不能通过猜测取得资格。保留来源身份但未放行的正文仅供
   维护审查，不进入默认检索或向量索引。
8. 每次提升保留来源字节 hash、范围、用途、条件、审查者、开放问题与版本关系。
   局部修复通过仅关闭该范围，不能替整个章节或来源背书。
9. 来源疑点不等于无价值。保存原始观察与有依据的解释；可唯一推导时照常计算并
   单独标记推导，未唯一闭合的部分保留不确定性。

上述内容门不增加 QA 数量，不要求逐符号/单元格拆分或复杂字段；来源、许可、
候选、项目隔离和身份核验仍是管理边界，不是逐点内容考核。内容门通过只表示该
知识块可读、可复述，不代表已执行软件/工程运行或完成工程验收。

## 当前可调用能力

- `tools/expert_cli.py --query <问题>`：原节点与设备事实统一入口；安装后位于
  `{CHEM_WORKSPACE}/chemical-engineering-runtime/tools/expert_cli.py`。
- `knowledge/scripts/query_knowledge.py`：复用原V10评分逻辑的标准库查询，按
  corpus、节点ID、宏观/细节需要定位。`--vector` 复用原工作区哈希向量与路由
  评分，并非另训练语义模型；依赖随包NumPy，索引在 `knowledge/vectors/`。
- `knowledge/chemical_principles/knowledge_graph/`：原有23张思想/机制/方法卡；
  Sun Lanyi通用节点和V10细节分别在各自corpus内。来源页未随包时仍须按原页
  核验门处理数字，不伪装已经查看原页。
- `--node-id` 按精确身份下钻，`--detail` 请求计算细节，`--full-text` 返回已放行
  节点的完整文本。正文未放行时返回其身份与原因，不从网络补取。
- `knowledge/scripts/build_knowledge_version.py` 在独立目录构建知识候选版本；
  源节点、审查、记录和向量保持对应，日常检索不修改正在使用的库。

## 检索与评测边界

先过滤项目范围、版本、候选/隔离、来源可用性和准入状态，再作相关性排序与
图关系展开。向量命中只定位依据，不能提高事实权威。

当前本地 768 维索引是确定性字符/词项哈希表示，不能称为已训练语义 embedding。
相关性排序不代替准入审查，也不代替公式、续表和流程关系的逻辑完整性检查。
普通 JSON 字段说明文档不能冒称完整可执行 JSON Schema 验证器。

补充来源资料时，在独立候选目录验来源、资格、关系和审计，再与现有知识对齐；
不能用统计数或旧 OCR 伪造缺失的人工解释及审核记录。普通来源入库与任务经验
进化分开：后者仍须用户确认任务结束，并通过既有血缘、禁学和候选审查门。
