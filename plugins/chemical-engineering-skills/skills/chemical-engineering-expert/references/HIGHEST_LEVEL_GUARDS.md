# 最高层：少量判断原则 + 按需强制学习

最高层是行为优先级，不是事实权威升级。新项目证据、物理约束和用户要求仍按 REASONING_PROTOCOL 判定。

## 四条常驻原则

1. **先判断任务与全局，再做细节。** 不绕过指定方法；流程收敛、设备有候选都不等于合理或优选。
2. **先保留简单可行基线。** 没有型号、缺资料、离目录参考点稍远，都不证明应增加设备。多台、分级和改路线必须针对真实限制，或有同基准全系统收益；不能为局部评分制造复杂性。
3. **改动必须闭环并可追溯。** 同版工况校核设备，选定改动回到真实流程复算；每台设备可回到输入、公式、约束、调整和复算证据。严格标准默认；用户放宽仅限当前任务，其结果及派生内容禁止自进化。未执行不说已验证。
4. **Aspen运行应无实际错警，求解容差锁定。** 核实当前运行结束、同次完整 Control Panel 消息和 `.his` 无实际错警，验证适用输入、模块、循环、衡算、产品等项目门。交付须无编辑复开并复跑精确文件。原生 Summary 用于诊断，只有明确要求全表计数证明时才将其列为必需证据。默认及已有求解容差保留原数值与默认/显式状态。[验收证据](STRICT_ACCEPTANCE_AND_LEARNING.md#2-aspen运行状态检查)

## 到点必读，不把大块细节常驻

- 新建完整流程、交可直接建首版的工艺文章或按该法修复，先读
  [docflow 全流程工作流](../../aspen-document-driven-flowsheet/references/fullflow_generation_workflow.md)。
  按当前阶段核对应证据。完整建模规划在交稿前由同模型、同档三位子代理独立审全链。
  进入骨架阶段后实际运行，再对同次导出做三份独立复核。逐模块核物性，存疑先查登记的外置专著。

- 查模型值、推导运行关系、匹配目标、扫描规律、多变量调参或优化：先按
  [内置工具规则](../../aspen-document-driven-flowsheet/references/aspen_builtin_solve_fit_tools.md)
  先分清研究问题、固定量和联动量，再调用 `solve_route` 并按相关判断链继续。
  固定控制响应不等于同产品优选；结果变化要反馈到比较基准与受影响下游。
  原生求解优先，外部脚本可建卡取证，不能凭工具名或外部扫描冒称原生执行。

- 每次真实交付说明本版范围与遗留，在用户可见的答复中询问该版是否完成或需要改进。按 EVOLUTION_LOOP.md 处理实际回复；用户明确结束后当轮整理由该版产生的本地复盘和拟上传表。已有确认或同一待答请求不重复询问，
  普通窄答复不附加泛问。提示词只凝练宏观设计原则与行事规则，数据规律留在相应下层；
  没有新价值就不改 Skill。

- 验收、用户放宽、错误学习或知识晋升：必须读 STRICT_ACCEPTANCE_AND_LEARNING.md；默认严格，放宽来源链只审计不学习，表头/公式纠错须靠真实来源。

- 做工艺安排/合理性判断：先读 MACRO_DESIGN_QUALITY.md；向常识 RAG 检索该问题的 L3/L2 约束，需计算再下钻 L1/L0。
- 从资料选路线、骨架已有负荷、严化岛、接回，或分析已发生/拟发生的工况与模块变化：按 DESIGN_STAGE_ROUTING.md 执行实际阶段调用并保存结果。每个严化岛以同版设备全清单选型反馈收尾，闭环后才回装；整厂接回后重新覆盖。只解释变化后的异常也属于 `change`，缺模型时用已有事实查询并保留缺项；无当前流程事件的身份核对、文件/措辞审查与纯原理等窄任务仍按既有范围执行。设备约束按 PROCESS_EQUIPMENT_FEEDBACK.md 返回工艺复算。不能仅列模块名或凭程序READY结束。
- 需要换热器拆分、压缩分级或其他设备回退：先检索该机制/方法和当前设备证据，读取相关规则后再执行；区分输入缺口、目录覆盖和真实能力限制。具体实现从现有专业Skill继续路由。

RAG入口与资格见 COMMON_SENSE_RAG.md。以上触发不是只“搜过”即可：实际使用的节点、适用条件、关键计算与证据缺口要进入当前任务账本。
