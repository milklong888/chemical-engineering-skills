# 设计阶段的实际调用

本规则负责把既有专业工作流接到真实查询和计算入口，不另立物性、设备算法或
验收标准。先读当前项目决定和错误记忆；从当前阶段继续，不无故重建已接受模型。

## 何时调用

遇到下表对应的设计事件，主工作流必须执行本产品运行根目录下
`tools/expert_cli.py`的`design_stage`操作，或同一实现的MCP
`design_stage_check`。先用`--schema design-stage`发现当前字段，不猜输入。
常驻JSONL会话可复用设备后台。结果用`--output`保存到当前项目的新文件，
并在阶段记录中引用；只列Skill名称、复制旧结果或写“已考虑”不算执行。

| 当前事件 | 阶段 | 必须做的专业工作及返回 |
| --- | --- | --- |
| 从任务书确定路线或重新选择方法 | `source` | 实际查询系统原则和适用机制，发现设备能力；来源提取及宏观合同由主流程完成。未形成工况时不要求最终设备尺寸。 |
| 获得完整简化骨架及初步负荷 | `scaffold` | 用明确标为初步的当前输入执行设备推导，查找数量级、温压相态和能力问题；简化假设不晋为正式依据。 |
| 严化或优化一个反应、分离、热泵岛 | `island` | 查询岛所用方法，按当前岛出口和负荷重算设备；塔、热泵、动力学等专项由各自Skill接手。 |
| 岛或工段接回已有流程 | `reconnect` | 用接回后的新导出重算受影响设备，重新核对入口、循环、热量、压力和产品；旧岛结果只作对照。 |
| 变更记录或当前观察显示负荷、温压、相态、物性、几何或连接改变 | `change` | 重新查询变化涉及的适用条件并执行当前数据支持的设备计算；记录压力及其他受影响结果，不能沿用旧版通过标签。只查变化导致哪些假设失效也属于此分支。 |
| 准备完整流程交付 | `delivery` | 核对授权范围内设备覆盖、同版计算及修改后的复算证据；需要反馈复核时调用既有回执检查，最终软件验收仍由操作模块执行。 |

这是阶段检查，不是逐次设置卡片都重跑所有模块。相同来源、同一工况和同一阶段
内可引用已有有效收据；任何会使输入或适用性过时的改变，必须生成新收据。
只有查定义、换单位、组分模板、提取既有费用或修改文字排版时，直接走所需的小
工作流，不为获得阶段收据而编造设备清单或要求全厂模型。

“先审安排、不运行模型”仍可以是上述设计事件：按现有资料执行对应阶段的知识
检查，缺少工况的设备项保留缺口。已发生的相态或入口变化也触发 `change`，
不等助手实际修改模型才检查。`solve_route` 只处理工具分类，独立知识查询只处理
检索；两者均不代替适用的阶段操作。没有设计事件的窄问题仍按上一段处理。

阶段由当前工作对象决定，不能按手头资料多少降级。已有可行塔或岛的优化安排
使用 `island`；缺少模型导出、运行身份或设备工况时仍调用该阶段，接口会执行
可用知识查询，并逐项返回缺口。不要为了避开这些缺口改报 `source`，也不要编造
身份、哈希或设备数据。只有重新确定路线/方法的工作才属于 `source`。

知识准备所需的最小有效请求包含当前 `stage` 和实际 `question`；例如既有岛的
安排审查可以从下面的结构开始，再只补本次有依据的字段：

```json
{"operation":"design_stage","payload":{"stage":"island","question":"审查现有塔岛下一步优化安排"}}
```

这个请求不会证明当前模型或设备已经校核；它应保留相应身份和计算缺口。

CLI 的请求外层必须是 `{"operation":"design_stage","payload":{...}}`，
具体 payload 以当前 `--schema design-stage` 为准。保存后分别核读：

- `stage` 与顶层 `status`：当前阶段及阶段检查结果；
- `solve_route.status`：阶段程序是否执行了路由调用，如 `EXECUTED`；
- `solve_route.result.status`：路由本身的实际结论，如 `AGENT_CLASSIFICATION_REQUIRED`；
- 查询及设备项目各自的实际响应、缺口和失败。

`EXECUTED` 不能代替路由结论。独立 `solve_route` 回执则直接读其顶层
`status`。对照实际返回结构，不把这些不同层次都缩写成“检查通过”。
`execution_summary` 汇集阶段、路由与逐项压力计算的实际状态及原始错误；查询和设备仍逐项核读。
其中 `pressure_checks[].call_status` 只说明调用状态；继续读 `check_results` 的
`result_present/status/reason`，不能把 `EXECUTED` 当成本项已经算出结果。
摘要没有压力条目时仍核读 `needs`，区分未声明检查与整个检查列表无效。
参数名、结构或类型错误先按当前 schema/函数签名修正；只有现有输入和权限足够时重调。
不继续计算也须准确报告原错误和当前未完成范围，不能把接口拒绝改称缺模型、
缺软件或物理不可行。真实数据缺口与调用错误可以同时存在，分别列明依据。
缺少内层结果显示 `NOT_AVAILABLE`，
便于先读摘要再核对应回执。重复的嵌套 `solve_request.question` 与当前问题不一致
时仍拒绝该调用；按返回提示更正后取得新回执，不把顶层阶段状态代替失败的路由。
`change` 的 `planning_requirements` 只保存尚未执行的交接要求，不能证明已找到或
复制模型、选定修改、重放或回退。主助手仍需按当前任务填出具体候选、依据与比较项，
缺文件时列实际依赖；字段存在不表示项目专属修复方案已完成。
收尾前补做当前资料足以支持而尚未执行的检查，分别报告缺数据、调用失败和待实施，
不要把列出的后续计划记为已经完成。

## 求解工具在阶段内怎样介入

建立依赖关系或开始调参前，按
[内置工具规则](../../aspen-document-driven-flowsheet/references/aspen_builtin_solve_fit_tools.md)
判断这是读值、一次推导、运行时联动、范围分析、目标匹配还是优化。阶段请求
可以带 `solve_request` 明确这一判断；否则入口根据当前问题给出有限提示。
它返回 `solve_route`、按问题裁剪的 `decision_chain` 及必读方法，命中后必须
继续相关判断和专业实施，不能只保存收据。可用 `solve_request.study_context`
记录研究变量、保持条件与内层控制；它不替换本阶段的工程身份 `context`，
也不证明这些声明已经核实。
未识别的说法由主代理补充分类，不把词面没有命中当作“无需工具”。

Calculator 在依赖它的单元计算前建立，纯统计则在结果形成后计算；Sensitivity
用于未知响应/区间，Design Spec/Vary 用于有真实自由度的目标闭合，Optimization
用于可行基准上的约束优化。同产品基准比较时，每个外层工况内重解必要质量
控制；明确研究固定操作响应时保持相应设置，不强行切换成同纯度分析。
只是读取结果或一次换算时直接调用独立 `solve_route`，不编造设备清单。

路由不启动 Aspen、不创建原生对象，也不批准外部替代。其待办只能由专业流程
的真实建卡、导出及同案结果回应；阶段检查仍可继续完成不受影响的知识和设备
计算。输入/对象不变时复用有效区间，发生物性、边界或控制变更后重查适用性。

## 查询怎样约束设计

阶段入口实际执行分层知识查询。主代理必须检查返回节点的来源、适用条件、
正文可用性和证据等级，再按节点ID读必要原文；程序返回一条命中不证明已读懂
或已采用。先回答系统安排是否合理，再读机制与计算细节；项目数值仍来自当前
资料、同案导出或可复算推导，不从向量相似度继承。

节点不足时继续目标检索、当前源文提取和确定性推导，列出影响该项判断的最少
缺口。可以继续不受影响的工作，不把查无命中误写成物理不可行。

## 设备怎样反过来限制模型

先建立授权范围内的物理设备清单，对照同案导出说明模拟块与真实设备的关系。
逻辑混合/分流节点不自动算一台设备。阶段入口逐项调用现有设备程序，即使其中
一项失败也保留其余实际结果；主代理仍须核对清单覆盖及公式适用性。

设备输入与当前来源、版本及单位对应后，有适用能力限制时使用既有
`feedback`路径。先排除单位、提取、机制和目录覆盖问题，再依据
[设备反馈规则](PROCESS_EQUIPMENT_FEEDBACK.md)比较分段、分级、并联或工况调整。
换热面积限制可筛查串联分段，压缩压比限制可筛查串联分级，塔通量限制可筛查
并联；它们都不是遇到无型号就机械拆分的规则。

采用修改前更新项目变更表，之后由专业Skill与操作层真正改模型和运行。重新
读取受影响物流、循环、控制、产品、热量、压降、设备和费用；未复算项保留失效
状态。压降使用各自适用方法，串联逐段累计，并联满足共同边界压差，不把支路
压降相加。设备算法不能计算的正式评级送EDR、塔水力学或相应厂家证据路线。

## 怎样判断已经完成这一阶段

收据记录实际查询、请求和响应及其身份；`MODULE_CHECKS_EXECUTED`至多表示
所列模块检查已执行，`ACTION_REQUIRED`表示还需行动。两者都不是工程通过，
`engineering_accepted`不由这个编排器设为真。自报PASS、退出码0、文件哈希或
一台设备成功，都不能代替源文审查、设备覆盖或真实软件验收。

阶段总结要写明采用了哪些节点及原因、计算范围和结果、未闭合项、影响对象、
下一步和收据路径。原有`record_process_slice.py`仍用于项目审计，不能凭它
保存的自报状态晋级。最终Aspen候选的完整版本表头、所有错误警告为零、原始
历史、精确文件复开及产品等门，继续复用`aspen-plus-operations`，不复制
另一套解析器。资料、设备计算和软件验收的职责不能互相替代。

若统一入口不可用，先修复已安装路径或依赖；有既有可执行入口时可直接调用同一
检索和设备程序，保留等价原始结果与范围，并明确记为手动检查，不伪造阶段收据。
真实缺失仅阻断受影响阶段的完成声明。MCP不可用而CLI可用时使用CLI。
