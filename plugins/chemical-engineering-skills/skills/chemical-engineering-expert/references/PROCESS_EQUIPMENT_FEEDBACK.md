# 流程—设备可实现性反馈

适用于流程构建、重大工况调整、模块合理性审查及流程交付。用户于 2026-09-09
明确要求设备选型器用于检验工艺参数与模块，超出能力时回退调整流程，并让每台
设备的选型可追溯。本规则是当前工作习惯，不承诺软件能独立证明整个流程合理。

## 两条能力与一个闭环

`常识 RAG → 原理/适用域 → 工艺路线与参数 → 设备程序校核 → 修改候选 → 流程重算 → 同版追溯`

常识图谱提供有来源的机制、方法、趋势、限制和判断依据。设备程序在当前工况上
执行公式、比较登记条件、生成型式和规格候选，必要时返回多台或专项设计建议。
专家层判断诊断原因、选择修改并验证全系统影响。程序有候选不能替代物料/能量、
相态、压力、循环、产品、公用工程和可操作性检查。

## 每个工艺模块的校核合同

保留项目/候选版本、Aspen 文件和导出 SHA、模块 ID、物理用途、入口出口流股、
相态、流量/组成/物性、温压、热负荷/轴功、允许压降、运行包络及来源单位。
工艺模块与物理设备允许一对多、多对一；把映射写清，逻辑 MIXER/FSPLIT 节点
不自动算作独立设备。

先执行所有可闭合计算，再读取参数包、计算追溯、终选规则、约束诊断和调整方案。
保留直接输入、确定性推导、经验/默认估算的分别来源。对照设备需求与能力，
区分以下原因；一个设备可同时带多项诊断：

| 原因 | 下一步 | 能否由此直接拆设备 |
| --- | --- | --- |
| 输入/基准错误 | 修正单位、绝压/表压、量纲、相态、符号、来源或异常值；重算 | 否 |
| 物理机制冲突 | 回到物性、模块、压力路径或热量温位，修复工艺原因 | 否，需先证明方案解决机制冲突 |
| 经适用证据确认的单机容量/操作包络冲突 | 比较多台、分段、分级、改型或工况调整 | 可形成有条件候选 |
| 目录覆盖不足/数据库未加载 | 恢复正确资产、扩展适用目录或转专项设计 | 否，未命中不是物理极限 |
| 输入或正式设备证据缺口 | 推导可推导项，保留初步结果，列最小关键缺口 | 否，缺厂家型号本身不是超能力 |

源码中的通用拆分阈值属于登记的初筛策略，须标为 `J/provisional`。只有当前
设备型式、材料、制造、运输、厂家/软件范围支持的界限，才能作为本项目能力证据。

## 先保留简单可行基线，再决定是否增加设备

靠近目录参考点、拟合距离变小或局部评分改善，不等于单机不能完成任务，也不
等于多台更好。先检查同工况单机基线；多台/分级/改型必须有真实约束，或经过
同基准性能、能耗、投资、控制、维护和可靠性比较的收益依据，才能进入实施。
程序建议原样保留，但把理由仅为目录距离优化的多台方案标为
`complexity_not_justified`，不能自动写回流程。

本次合成回归中，普通泵仅因目录距离优化即返回6台运行加2台备用，是上述门的
反例，不是可迁移的设计配置。缺输入导致的泛型 `plan.triggered` 也不构成
压缩分级依据；先补数或闭合计算。具体证据见接入目录的独立审计与桥回归。

## 换热器回退

1. 先查热负荷、两侧温度曲线、相变、U/F 的来源、允许压降、污垢和设备型式。
   温差不可行不能仅靠面积均分修复。
2. 超单机面积、流量或可制造尺度时，比较并联列；温度区段、相态或不同热源
   不兼容时，比较串联分段、相变段分离或热源重新匹配。
3. `N=ceil(A_required/A_allowed)` 只在 A_allowed 有适用依据时给出台数初筛。
   `Q_i=Q_total/N` 与面积均分是假设，须满足真实分流和每列负荷；并联压降不能
   直接除 N，串联热负荷也不能在不重算中间状态时平均分配。
4. 重新计算各台进出口状态、热负荷、面积、冷热侧流速、压降和控制/隔离方式，
   保持总热量与流量闭合。需要时由 EDR 做同工况设计/评级。
5. 回到公用工程层，比较预热回收、温位匹配与压缩升温；新增换热器不能掩盖
   高品位热源使用不合理或热量重复计入。

## 压缩机回退

先查绝压压比、气体组成和相态、吸入口体积流量、温升、轴功、允许压力/转速/
操作包络。并联主要分摊流量，串联分级主要分摊压比；二者不能互换。

若单级条件不合理，筛选多级与级间冷却/气液分离，逐级重算物性、压比、排温、
功耗、冷却负荷、冷凝与液滴风险、压降和防喘振/控制。相变、反应或不适合冷却
的介质须按当前过程模型处理，不能强套理想干气路径。

等压比 `r_stage=r_total^(1/N)` 只在理想化、相同条件下作为初始化。若用户/
适用设备资料已给出 r_allowed，可用对数关系初筛 N；仍须纳入级间压降、非理想
物性和机器包络复算。禁止把任意通用压比当已验证单级上限。

当前接入的 selector 已有压比等计算，但尚无自动压缩分级调整分支。仅在用户
要求分级评审，或同工况的适用能力证据显示需比较分级时，返回
`staged_compression_screening_required`，由专家按上述方法形成项目候选并交给
Aspen/相应计算工具验证。正常压缩机不因程序缺少该分支就强制回退，不能宣称
软件已自动完成分级设计。Aspen COMPR 也可表达膨胀透平；先核对物理用途，
只有明确要求升压而出口压力不大于入口时，才把方向列为压缩用途的输入冲突。

## 回退是受约束的设计迭代

- 固定产品产量/纯度/回收、系统边界和用户要求；具体工况、台数或拓扑修改先
  写入项目 change-offset。当前授权已涵盖的调整直接推进；用户明确禁止的
  拆分、设备添加或路线改变仍是限制。
- 保留原候选，在受保护副本上实现选定方案。返回程序建议仅代表候选，须真实
  修改、重算和导出后才算实施。
- 标记当前设备、相关流股、上下游单元、循环/设计规格、热网、泵压缩功、公用
  工程和经济基准为需复算；逐项闭合，不能只更新设备清单。
- 若本轮未改善已识别原因，或只是重复同一失败候选，调整假设/方案层级；当缺
  关键设备能力证据时保留有依据的初步方案与缺口，避免无限重复或假装完成。
- 最终在同一版本验证 Aspen 原有交付门与产品/全系统门，并给出适合当前设计
  阶段的设备覆盖和证据状态。正式采购还需要厂家/机械证据，不能把其缺口改写
  成所有初步流程工作必须停下。

## 逐设备追溯的最低记录

`project/candidate -> source file/export hash -> module/stream identity ->
input value/unit/basis/source -> formula and code hash -> parameter package ->
rule/condition/feature hash -> diagnostic -> adjustment plan hash ->
old/new equipment mapping -> affected consumers -> rerun/export hash -> acceptance state`

一台模拟设备拆为多台时，记录父模块 ID、各子设备 ID、数量/连接方式、分流或
中间状态与重算关系。总表每行能回到当前候选的输入、公式、来源和校核结果。
不能将另一个候选、旧版参数或仅声明 `traceable=true` 的字段当作有效追溯。
