# 收敛诊断案例与方法参考

分类：案例/方法参考，按症状读取；不是常驻求解规则、运行成功案例或默认参数。这里整理可选诊断思路，正式诊断与同案复跑仍归[修复工作流](../repair_workflow.md)，Aspen执行与消息解释仍归操作Skill。

| 触发症状 | 参考方法 | 适用边界与反例 |
| --- | --- | --- |
| 多个控制或数值设置共同出现时才失败 | 保留完整基线，围绕明确假设比较整组、去除组与子组；若子组分别不复现而合组复现，追加耦合/执行顺序核查 | 只在已获准改动、仍保留真实物理职责的分支使用；导入失败或新增物理失效的分支不能排除原根因；分组结果不自动证明因果 |
| 外层目标残差停在平台 | 先读内外层各自变量、单位、相对/绝对准则、写入者、执行顺序与实际响应，再判断是否具有可比性 | 无量纲相对残差不能直接与有量纲产品容差比大小；平台也可能来自自由度、噪声、边界或错写变量，不能直接断言内层精度不足 |
| 保存解能跑通，但起点或进料变化后失败 | 区分保存解热启动、已证明原始初估的冷启动和允许范围内的初值扰动；同源、同目标比较真实运行响应与覆盖 | 新文件名、新会话或清缓存标签不证明冷启动；初值恰好达标只证明该点结果，不证明控制器发生有效响应；不未经授权启动批量运行 |

## 精度冲突如何处理

原参考讨论过验证更严内层容差。本Skill当前[精度锁](../../../chemical-engineering-expert/references/STRICT_ACCEPTANCE_AND_LEARNING.md#2-aspen运行状态检查)禁止为收敛而修改默认/既有容差，因此该建议只保留为来源冲突说明，不能跟随案例执行。可以查清量定义和误差传递、比较已有合格观测；若研究确需改变精度，先交回当前任务权威处理，不自行改合同。没有通用的1e-6、迭代数、tear位置或初值。

试验开始前按[试算组织规则](../../../aspen-document-driven-flowsheet/references/aspen_convergence_trials.md#branch-control)落实当前用户的预算、停止条件及待更新项；案例不提供固定迭代次数。

## 只在需要离线辅助时查看工具

经验库已有三个独立工具职责：[受限文本变体、精度观测审计、冷启动观测审计](https://github.com/milklong888/chemical-engineering-experience-inbox/tree/03f436d3942086084a59ed6cfd9853f7c615ca55/pool/scripts/convergence-diagnostics)。先核当前接口、来源版本和输入适用性，再使用现有副本；不在项目复制第二套COM、锁或错误计数器。工具只处理明确给定的文本/观测，不能证明真实Aspen初始化、因果关系或工程通过。缺工具不妨碍按本页核查现有证据。

记录触发症状、来源/原假设、受保护基线、允许改变的量、正反对照、真实输入与同次输出、无效分支和剩余解释。需要“更快/更稳”结论时还须有可比计时、边界与未参与调参样本；本页没有这样的性能声明。
