# Comparison Cost Completion

## Purpose

The strict engineering field may remain unresolved, but every row used for
route comparison must have a numeric contribution. The script keeps both:

```text
raw_engineering_cost_usd   # nullable, source-faithful
comparison_cost_usd        # always numeric
```

Structural exclusions contribute numeric zero with `structural_zero=yes`.
Physical equipment uses the ordered IF rules in
`comparison-cost-fallback-policy.csv` and never silently becomes zero.

## Scaling

For a qualified positive proxy ratio:

```text
if comparison_scale_ratio is supplied:
    ratio = comparison_scale_ratio
elif proxy and a source-backed reference proxy are supplied:
    ratio = proxy / reference_proxy
else:
    ratio = null  # use the registered reference cost without scaling

if ratio < 0.25:
    effective_ratio = 0.25
    train_count = 1
elif ratio <= 4:
    effective_ratio = ratio
    train_count = 1
else:
    train_count = ceil(ratio / 4)
    effective_ratio = ratio / train_count

C = train_count * C_ref * effective_ratio ** exponent
```

The reference cost is adjusted from its registered index to the case target
index before scaling. Missing case target index uses comparison index `816.0`
and records that default explicitly. A generated Skill never invents a reference
proxy from the current case. Optional input keys are
`comparison_scale_ratio`, `comparison_proxy_name`, `comparison_proxy_value`,
and `comparison_reference_proxy_value` inside `parameters_json`.

## Required output fields

Each item records raw cost, comparison cost, low/high comparison bounds,
generation tier, IF rule ID, replacement method, source and locator, proxy,
reference proxy, effective ratio, train count, structural-zero flag, replacement
reason, and review requirement.

Stage summaries always contain numeric central/low/high totals and the fraction
of cost generated by fallback tiers C/D/E. A high fallback share does not remove
the number; it marks the comparison as uncertain.
