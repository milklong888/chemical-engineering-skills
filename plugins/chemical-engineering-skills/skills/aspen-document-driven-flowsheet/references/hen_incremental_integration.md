# 既有 Aspen 流程接入换热网络

适用于将 HCH、配对表或换热网络图接入已有流程，也用于复核 HeatX 的选型及接入范围。由文档流程模块管理范围与对应关系，由操作模块实施和复核实际模型。只读审查可用已有记录完成。

## 建模前确认换热服务

核对当前用户要求、基准模型和 HCH 的有效设计情景。沿冷热两侧的真实流股与端点识别配对、串并联和顺序。在现有变更表中记录服务来源、物理用途、原设备、保留/新增/替换/待定动作、拟用模型、实际端点与验证方式。由这张表推出新增及改造设备清单。

- 两股工艺物流直接换热时，按当前模型要求建立双侧耦合。要求 HeatX 时，明确冷热侧四个端口，并核对换热方向、端点温差、相态和压降。
- 外供热和冷却按改造边界保留原 Heater/Utility，或按任务需要建立显式公用工程物流。工艺换热使用 HeatX 的要求只覆盖该类服务。显式公用工程、设备评级或 EDR 有单独要求时，按其范围建模。
- 反应器分布换热、塔内冷凝或再沸若已有设备承担，记录原设备及其热边界。经批准外置时，检查旧负荷是否正确转移及有无重复计热。相态适配和逻辑块单独标记。
- 分开记录空或缺失的 Duty、明确数值零、停用、旁路。即使负荷明确为零，仍需以项目范围和物理功能判断能否取消既有支路。热流方向有分歧时，结合冷热端的焓变化和原模型边界确认。

## 保留节能回路并分步实施

对要求保留的回路，改动前冻结驱动设备、放热侧、受热侧、回流或返回端点、压力路径及现有规格和控制引用。新增服务若需复用旧设备，先明确原功能由哪里承接。来源冲突影响保留范围时，先核项目决定和原件。仍需用户决定时保留该项待定，继续独立工作。

先验证代表性新增服务，再依次接回并比较导出的拓扑和控制引用。停用的 Design Spec 或 Sensitivity 也要核对旧流股引用。对于零负荷相态适配，用同案焓、压力和相态基准核对温度变化。

接回后分别核实底层模型、冷热端连接、原生图面、控制规格、衡算及产品。沿原回路核实实际功能。按同一基准分别报告原回收变化、新增回收、外供热冷及轴功，净节能沿用[热泵审查](../../aspen-heat-pump-distillation-replacement/SKILL.md#trigger-contract)。最终文件和目标版本沿用[操作与交付规则](../../aspen-plus-operations/references/operations_workflow.md)。
