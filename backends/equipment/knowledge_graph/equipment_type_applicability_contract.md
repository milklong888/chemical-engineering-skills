# 多类型设备双侧标签与唯一终选契约

## 目的

本节点处理标准、手册、产品系列或类型介绍中“列举多种型式并说明各自特征”的内容。它适用于垫片、法兰、密封面、紧固件、阀门、管件、塔内件、换热器结构、分离器结构、泵型、压缩机型、搅拌桨、材料路线及其他多类型对象，不是垫片专用规则。

运行时不得依赖 PDF、图片、视觉模型或大语言模型。知识图谱必须先形成来源锁定的双侧标签和规则，脚本只能消费已验证的数据。

## 双侧标签

### 工况侧 `service_labels`

工况标签由程序从当前设备的 Aspen 流股、模块、PFD 拓扑、确定性推导和有来源的物性/相容性子图谱自动生成，用户不负责贴标签。手动模式也只接收原始工况字段，再走同一自动标注器；直接提交标签不能绕过来源、单位和推导校验。每个标签必须携带值、单位、压力/温度基准、来源字段、来源哈希、推导规则、证据类和置信状态。具体边界和顺序见 `equipment_service_label_derivation_contract.md` 与 `equipment_service_profile.schema.json`。

至少覆盖：

- 设计/操作压力与压力基准、真空、PN/Class 目标；
- 设计/操作温度、最低温度、温度循环和热冲击；
- 气/液/两相、固体夹带、黏度、密度及可用的组分/物性；
- 腐蚀、冲蚀、结垢、聚合、堵塞倾向；
- 可燃、氧化、毒性、逸散/泄漏敏感、火灾安全；
- 洁净/卫生、可清洗、蒸汽吹扫、重复拆装；
- DN、PN/Class、法兰标准、密封面、材料组和连接约束。

Aspen 只证明流程工况与物性。它不能自动证明腐蚀等级、毒性等级、洁净等级、法兰正式等级、密封面、材料相容性或厂家性能。腐蚀、毒性、可燃性等标签必须由“流股组分及含量 + 温压/相态 + 有来源的物性或相容性图谱”确定性连接得到；不能按组分名称或模型常识猜测。未被同工况来源支持的标签保持 `UNKNOWN` 并报警。

### 候选侧 `capability_labels`

每个登记类型必须有稳定 `option_id`、终点名称、来源支持的能力/限制标签、硬排除、必要兼容条件、偏好条件、泛用性顺序、是否可作默认及默认告警。

候选标签可描述：温压包络、介质/材料相容、相态、固体/结垢、泄漏、火灾、洁净、循环、密封面、PN/Class、DN、材料组、制造/软件/厂家边界。标准没有给出数值边界时不得自行补数值；只能登记为文字条件或外部证据门。

## 来源文字与补充解释

每个原文片段保留文件 ID、文件 SHA-256、页码、bbox、表/图/段落 ID、原始文字和复核状态。机器友好的补充句与原文分栏，使用以下分类：

- `SOURCE_QUOTATION`：原文短句或表注；
- `SOURCE_PARAPHRASE`：不改变含义的来源释义；
- `ENGINEERING_NORMALIZATION`：把原文特征映射为统一标签；
- `DETERMINISTIC_DERIVATION`：由已给数值和登记公式得到的条件；
- `EXTERNAL_CANDIDATE`：待验证外部知识，不得进入生产规则。

`ENGINEERING_NORMALIZATION` 和 `DETERMINISTIC_DERIVATION` 不能伪装成标准条文，必须引用其依赖的来源和规则版本。

## 确定性唯一终选

固定顺序如下：

1. 先按设备边界自动汇集入口、出口、侧线和公用工程流股，区分物料流与能量流；再归一化工况标签，隔离坏单位、哨兵值和来源冲突；
2. 执行硬排除，命中即删除候选，辅助分值无权恢复；
3. 执行必要兼容条件，已知为假则删除，未知则保留为 `PROVISIONAL` 并登记最小缺失字段；
4. 在剩余候选中按“已闭合的条件选定 > 缺口更少 > 更泛用 > 来源等级更高 > 稳定默认顺序 > `option_id`”作字典序排序；
5. 输出恰好一个终点：显式指定且无已知矛盾为 `EXPLICIT_TERMINAL_TYPE_SELECTED`，条件闭合为 `CONDITIONED_TERMINAL_TYPE_SELECTED`，否则为 `DEFAULTED_TERMINAL_TYPE_SELECTED`；
6. 默认结果必须标 `J/provisional`，列出假设、未决条件、拒绝理由、最小缺失字段和告警；
7. 候选集可以保留多个，但终点字段不得为空、不得包含“或/待定/其他”、不得伪造厂家型号。

数值分值只用于显示匹配程度和回归比较，不能覆盖硬排除、必要兼容、来源边界或正式证据门。

## LLM 边界

模型可读取冻结的原文、归一化注释、标签目录和登记条件，并把自由文字映射到已有 `label_id`/`condition_id`。模型不得新增类型、数值包络、硬排除或正式型号；程序必须校验 ID、来源哈希和上下文哈希并完整重放，最终结果仍由确定性引擎产生。

## 数据与验收

- 类型图谱契约：`equipment_type_applicability_graph.schema.json`；自动工况画像契约：`equipment_service_profile.schema.json`；
- 通用标签目录：`equipment_type_applicability_label_catalog.json`；
- 每个来源包还需 type catalog、source snippets、option capabilities、condition rules、source relations、defaults/warnings 和 no-LLM cases；
- 旧数据集和新增资料都要扫描“介绍各种类型/结构/形式/系列”的正文、表注和图注；
- 生产验收要求 `vision_capability=false`、禁止源 PDF/图片、所有关系端点存在、规则与来源哈希稳定、边界/冲突/缺值用例均恰好一个终点。
