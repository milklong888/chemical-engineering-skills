# 验证说明

当前版本为0.4.0，机器可查结果见[0.4.0验证记录](验证记录_0.4.0.json)。
本页第8节说明阶段调用与独立安装复测；第7节及旧记录只作为0.3.0历史基线。

## 1. 发布检查

发布检查针对实际发行目录，包括文件清单与哈希、文本编码、插件与技能入口、
安装定位标记、被分发文件的内容边界、说明文档链接以及压缩包回读。

文件变更后应重新生成发行清单，不沿用旧文件的校验值。安装前核对整个包；
安装后的路径定位变化由安装记录管理，原发行包保持不变。

## 2. 离线验证

离线测试可以验证文本解析、输入分类、候选边界、文件身份、目录保护、重复
安装、失败状态和逻辑计算。使用合成输入的测试明确标识其性质，不把示例输出
描述为真实Aspen结果。

本包中的INP示例只用于说明输入结构或检查逻辑；它们不是用户工程模型，也不
作为已通过项目验收的流程文件。

实际发布验证结果记录于发行清单和对应版本的发布说明。软件接口测试须说明
是否实际启动了程序、使用哪个版本，以及输入与输出文件的身份。

## 3. 工程验收

工程项目另行验证反应与物性方法、物料和能量衡算、循环、产品、设备、操作及
安全条件。软件解析器或安装测试通过不能代替这些工作。

Aspen的错误汇总表按经核对的版本结构解释，所有要求的错误及警告计数为零；
同时检查本次完整运行历史，不以单独成功短语替代日志证据。最终文件复开运行
及项目产品要求按专业工作流执行。

EDR、塔内件、SW6和厂家资料的结果分别保留其适用设备、工况、版本和来源。
初筛类型、建议参数、严格计算和正式交付分开标识。

## 4. 复现边界

同一文件哈希只能证明文件相同。计算复现还依赖软件版本、物性数据库、输入
基准、外部数据、求解设置和运行条件。缺少其中关键条件时，应说明能复现的
范围，不把未执行的检查列为通过。

文件访问守卫覆盖Python的open/listdir/scandir，网络守卫覆盖socket/DNS；这
不是针对任意恶意原生库的操作系统沙箱。离线pip使用无索引和固定hash安装。
这里的“原Aspen MCP通过”仅指列举和纯本地调用，不是70个工程操作全部验收。

新增检查分别覆盖设备原/新结果等价、标准事实与管路字段等价、原知识节点保全、
向量准入、串并联压力关系、反馈来源与复算链、依赖离线安装以及真实MCP握手。
精确计数及本次回执以新版本发布记录为准；接口存在不算通过。

```powershell
python -B tests/test_equipment_backend.py
python -B tests/test_process_feedback.py
python -B tests/test_mcp_offline.py
python -B knowledge/scripts/verify_knowledge.py
```

封存检查对数据库、数值向量和轮子使用 `BINARY_ASSETS.json` 的逐文件许可/来源
分类与hash，不采用“允许所有二进制”。缺少清单条目、原身份漂移、数值索引变成
对象pickle、数据库解压身份不符均拒绝。普通CSV可保留原UTF-8 BOM，避免仅为
格式统一改变已验证数据身份；配置和代码仍使用可核验文本。

没有在此版本验证真实Aspen流程、换热器评级、塔内件、SW6或厂家保证值。
MCP测试中禁止外部网络及COM创建，保留原有后台服务不动；退出的是本次自己
启动的测试子进程。协议通过与真实工程软件通过是两个不同结论。

## 8. 0.4.0阶段调用与工作流验证

本版保留原设备算法、知识记录、标准数据库、向量及离线依赖，新增阶段编排，
并为全部19个Skill补充自然语言工作过程。阶段程序真实调用既有检索与设备
后台，但不启动Aspen、不自动推进工程阶段。工程验收继续由原有专业工作流负责。

最终实现完成333项公共测试，其中331项通过，2项依赖私人项目的历史学习用例
按公开范围跳过。新增阶段测试16项覆盖高层节点首查、资料阶段无设备输入、
逐台执行、坏项后继续、缺少来源、清单范围、压力基准、旧结果和交付回执等情况。
静态工作流检查另有5项，检查段落和链接，不将它描述为模型行为认证。

在原工作区外安装了分离的运行时和Skill目录。最终实现重新通过7项实际入口测试、
16项阶段测试和6项完整反馈示例测试，并直接核验安装后知识文件与owner定位。
MCP由真实SDK经stdio调用全部8个工具；Python主进程和子进程的审计守卫未发现
意外联网、COM或原工作区读取，入口测试的20个受守卫进程均已退出。此守卫不是
针对恶意本地代码的操作系统隔离环境。

另外18项设备调用层和25项知识生命周期测试在源码树执行，全部通过。它们自身
不支持安装目录环境变量，因此单独计为源码回归，不冒充已安装目录的测试。
实际安装目录中的知识查询、设备计算、阶段调用及MCP由前述入口测试覆盖。
日志身份与各组结果见[本版验证记录](验证记录_0.4.0.json)。
