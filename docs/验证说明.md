# 验证说明

当前发行版为 0.4.11。本次许可、文档与历史入口维护的实际检查见
[0.4.11 维护记录](维护记录_0.4.11.md)。此前完整工作流的测试保留在
[0.4.10 验证记录](验证记录_0.4.10.md)；更早版本移入[历史归档](archive/README.md)。
不同版本的测试数和文件哈希不能混用，也不能相加成当前测试总数。

## 发布完整性

发行检查覆盖实际包内的文件清单、哈希、编码、19 个 Skill 入口、插件结构、
内容边界、文档链接和 ZIP 回读。文件变化后重新封包，不以旧校验值证明新文件。
安装器按清单安装当前运行内容；`docs/archive` 不安装为活动 Skill 或知识节点。

版本身份须成组使用：Git 标签、同版 `RELEASE_MANIFEST.json`、
`SHA256SUMS.txt`、ZIP 及其 `.sha256`。主分支允许在发布后更新文档，
因此核验旧下载包应取对应标签，不应拿后来的主分支清单校验旧 ZIP。

## 本地工具与程序回归

本地检查可以证明解析、路由、文件身份、安装保护、确定性计算和失败边界。
使用合成输入的测试不代表真实工程已运行。专家 MCP 当前登记 10 项工具，
其接口测试与原 Aspen MCP 的操作能力分别计数；能列出工具不等于每项都已在
真实 Aspen 中验证。

主要复验入口如下，实际结果及跳过原因应另外保存：

```powershell
python -B -X utf8 -m unittest discover -s tests -p 'test_*.py' -q
python -B -X utf8 tools/verify_release.py
python -B -X utf8 tests/test_standalone_entrypoints.py
```

完整隔离部署测试另需要已登记的离线依赖环境。缺少私有工程证据或商业软件时，
对应测试如实跳过或待验证，不填造正例。历史测试命令、当时的包数和结果
在归档中保留，不代表现行全部执行结果。

## 真实工程验收

Aspen 交付要对精确文件无编辑复开运行，检查完整且经核实版本的 Summary
所有错误、警告计数为零；同次 Control Panel 消息和原始 `.his` 也不得含实际
错误、警告。默认及已有求解容差的数值和默认／显式状态应与修改前一致。
这些通过后，仍须核对产品、衡算、循环、物性适用性、设备和目标版本兼容性。

EDR、塔内件、SW6 及厂家结果各自绑定设备、工况、软件版本与来源。
初步选型、软件评级、厂家定型与正式工程交付分开标识。知识命中、阶段回执、
程序回归及安装成功都不能替代上述证据。

同一文件哈希只证明字节相同。计算复现仍依赖软件版本、物性数据库、输入基准、
外部数据与运行条件；关键条件缺失时，只说明实际能够复验的部分。
