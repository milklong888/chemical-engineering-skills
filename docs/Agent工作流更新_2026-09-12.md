# Agent 工作流更新：任务组织、执行核查与经验复用

2026 年 9 月 12 日

今天，我们完成了一轮面向 Agent 工作方式的更新，并发布 0.4.6 及配套的公开经验收件库。本次重点是组织已有能力、明确工具调用与协作关系，并打通经验整理、审核和后续维护的流程。

我们参考了技能组织、上下文管理和自进化方面的研究，将适用的思路落实到任务入口、维护工具和经验管理中。以下介绍今天实际完成的改动，以及现在可以怎样使用。

## 按任务组织能力，明确协作关系

[Group of Skills](https://arxiv.org/html/2605.06978v1)讨论了技能之间的分组与协作关系，[SkillX](https://arxiv.org/html/2604.04804v1)区分了规划、功能和具体动作的不同粒度。我们据此整理了当前库的任务登记：为现有 19 项 Skill 明确接手条件、所需输入、交付产物、协作对象和不适用范围。

现在，Agent 可以从任务目标进入对应模块，确定由谁负责主线、哪些能力按需协作，以及结果应该交回哪里。原先分散在多处的选择表已合并，主任务与辅助任务的交接也有了统一入口。

这次调整保留已有能力的职责分工，落地的是任务导航与交接规则。具体入口见[任务与协作登记](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/ACTIVE_ASSET_REGISTRY.md)。

## 精简重复入口，保留必要上下文

[SkillRAE](https://arxiv.org/html/2605.10114v1)关于上下文组织和原始约束连接的讨论，为本次入口整理提供了参考。我们精简了重复导航，将总入口保留为必要判断和任务选择，详细方法留在对应模块，通过引用按需读取。

现在，窄任务可以直接进入所需部分，复杂任务再沿协作关系展开。维护规则时也能找到原始位置，避免把同一段要求复制到多个入口后分别修改。本次采用的是导航与引用整理，没有加入论文中的自动上下文编译器。

## 新增决策树和两项维护工具

决策树为任务选择、工具使用、排错和经验维护补充了分支。每个判断都保留“有证据成立”“有证据不成立”和“未知或冲突”三种结果；信息不足时，先获取能区分分支的证据，再决定下一步。

配套新增的两项工具已经可以在本地运行：

| 工具 | 现在可以做什么 |
|---|---|
| 文件组织与影响索引 | 盘点当前库的 Skill 文件及引用关系；指定改动文件后，列出可能受影响的文件、相关模块、传播依据和未解析项。 |
| 运行记录观察索引 | 读取显式列出的结果文件，核对哈希和指定身份字段，分别报告文件缺失、内容变化、身份冲突和未观察状态。 |

这些工具为维护者提供具体的复核清单。影响索引分析静态引用，观察索引检查文件与有限身份信息；运行是否成功、规则是否适用，仍需依据实际结果判断。[决策树](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/TASK_DECISION_TREES.md) · [组织与影响索引](skill_organization.md) · [观察索引](observation_index.md)

## 把经验复用接入既有维护流程

[Reflexion](https://papers.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)和 [ExpeL](https://arxiv.org/abs/2308.10144v2)为反馈整理与经验复用提供了研究参考，[ACE](https://arxiv.org/abs/2510.04618v1)强调的局部更新也帮助我们复核了现有维护方式。本次工作的重点，是把临时经验收集与正式规则采用接到同一套明确的流程中。

现在，助手可以先处理当前任务的问题，再将有复用价值的方法整理为候选，记录触发条件、实际证据、适用范围和内容版本。已有同类规则时，先检查是否可以合并或补充，而不是再建一个同义条目。

正式采用仍沿用现有资格检查和候选评估工具：用户发起整理并确认相关任务版本完成后，核对已有规则、冲突、反例和回退依据，由维护者决定采用、细化、替换或撤回。更新落实到原规则的维护位置，保留历史与受影响范围。

这一流程维护的是 Agent 的提示规则、操作方法和外部记忆，基础模型参数保持固定。临时经验不会自动进入正式规则或默认检索。[经验维护流程](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/EVOLUTION_LOOP.md)

## 开放候选投稿，加入主动提醒

我们建立了[公开经验收件库](https://github.com/milklong888/chemical-engineering-experience-inbox)，在该仓库中新增收件校验与 GitHub 检查观察工具。使用者现在可以让自己的助手准备候选摘要，在授权公开后提交 PR，由维护者核验收件。

已执行的方法需要核对准确版本、相关运行、结果及其适用范围；思想原则先确认具体内容，再由助手审核。Git 提交和检查状态用于核对执行身份，不能单独证明经验已经成立。

全部 19 项 Skill 已接入阶段收尾提醒规则：出现有复用价值的新成果时，要求主助手展示具体摘要、适用条件和投稿入口。已有有效授权在其范围内沿用，拒绝或撤回后停止相应提醒和提交；多个子代理的候选统一交给主助手整理。

普通使用者可按[中文投稿指南](https://github.com/milklong888/chemical-engineering-experience-inbox/blob/main/docs/USER_SUBMISSION_GUIDE.zh-CN.md)完成准备和提交。公开收件与正式采用分别审核，安装后不会自动采集或上传其他任务的资料。

## 获取更新

任务入口、决策树、两项维护索引和经验提醒规则已整合到 [0.4.6 发行版](https://github.com/milklong888/chemical-engineering-skills/releases/tag/v0.4.6)。使用较早版本的用户可下载完整包，按[使用手册](使用手册.md)校验并重新安装；仅拉取源码不会更新本机已经安装的副本。收件校验与 GitHub 检查观察工具在独立的公开经验收件库中提供。

研究中采用的具体机制与本库的对应关系，记录在[研究采用说明](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/SKILL_RESEARCH_APPLICATION.md)。这些引用说明设计依据，不代表复现了论文系统或获得了同等性能收益。
