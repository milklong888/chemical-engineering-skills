# 0.4.7：把任务要求落实到查询、执行和交付

Skill 是助手在处理一类任务时读取的工作指南，连接相应的方法、资料和工具。此前，我们整理了这些指南之间的分工，加入了决策分支和经验收件流程。但说明写得完整，并不能保证助手在每个任务里都完成对应动作。

后续检查暴露了几类具体遗漏：回答提到了检查，却没有留下实际调用结果；做完局部工作，没有说明由谁接手；知道结论需要专业证据，却只解释了边界，没有查询；整理经验时能指出问题，却找不到应修改的实现。0.4.7 围绕这些遗漏修改入口、规则和配套检查，下面说明问题与做法。

这些修复建立在此前的任务组织上：19 项 Skill 按交付目标分工，入口说明接手条件、所需输入和返回结果，详细方法留在负责它的模块中。遇到未知或冲突，决策分支先要求获取能够区分方案的证据；修改规则时，文件引用索引用来找受影响入口，运行记录索引用来核对当前文件与版本。助手需要读取这些说明并调用工具，才能使用库里的方法；把文件安装到电脑上，并不会自动完成这些动作。

**要求查询和执行的任务，要交出实际结果。**

例如，已有条件发生变化，助手即使能解释变化可能造成的影响，也还需要完成当前任务要求的查询。此前有回答停在解释和后续建议，没有执行适用的阶段检查。

现在，入口先区分条件已经改变、准备修改和单纯阅读已有结果。需要阶段检查的任务，实际调用对应入口，集中返回查询、计算和路由的执行状态；缺少输入的步骤保留具体缺口。纯查问、文件核对和措辞修改仍按自身范围处理。

执行失败的原因也要与回执一致。阶段摘要补充了逐项压力计算的原始状态和错误，帮助助手区分调用完成与计算得到结果。请求参数错误按当前接口修正；确实缺少模型或数据时另列依据，不能用一种原因替换另一种。

查询要求也补到了专业审查入口。对证据归属或适用性不能确认的判断，要读取适用知识或查询相关接口，再把命中内容、使用范围和未解决的问题对应到当前结论。只说“还需要机械校核”，不能代替当前已经能够完成的依据查询。

**工具选择不一致时，要纠正请求并重新调用。**

达到若干指定指标，与在可行范围内寻找最优值，是不同的任务。此前出现过用户只要求目标匹配，助手却同时选择优化的情况。

本版要求求解路由在选择优化时收到明确的目标定义，以及最小化或最大化方向。缺少时保留候选意图并返回待分类状态，不输出已选优化路线。助手需要依据原问题补充真实目标，或者纠正误选后重新调用。返回的待办用于安排后续执行，不能被写成软件已经完成计算。

塔优化还要说明每个必要内层目标由哪个独立操作量调节，以及它的边界。没有证据支持额外自由度时，明确保留未定项和原有不等式约束，避免只写“逐点保持质量”，或让内外两层同时调整同一个变量。

**交接需要明确的范围、结果和负责人。**

局部工作能够继续推进，依赖的不只是文件存在。后续人员还要知道输入来自哪个版本、哪些部分已经完成、哪些仍是占位，以及最终结果由谁接纳和合并。

本版为流程安排补充边界与交接记录：明确计算范围内的节点，检查内部物流、流入和流出是否与申报一致；每个待完善部分列明接手条件、必要输入和必须交回的结果。未知端点和未定方法保留，不强行补齐。配套脚本检查这些声明的结构，实际数值和专业结果仍需相应核验。

检查还逐个核对过程节点的进出接口，避免循环只画出返回方向，却遗漏回收来源。来源尚不明确时，要列出具体的未决连接；只有资料确实规定该阶段没有相应接口时，才声明原因并保留来源核对要求。

交接记录中的授权依据和执行限制分别引用原文，防止转述改变允许范围。交付文件链接使用实际生成的完整路径，并检查目标存在，避免结果已经保存，使用者却打不开。

协作规则也明确了依赖顺序和最终责任。下游使用主助手已接纳的版本；多人修改同一目标时，使用独立候选或串行交接。主助手负责核对依赖、接纳结果，并完成最终合并。任务只要求规划分工时，交付这些责任安排，不虚构已执行的协作。

诊断任务暂不允许改模型时，也要说明后续保护哪份文件、取得什么证据后做哪一项修改、如何比较同案结果以及失败时回退到哪里。缺文件或缺证据就明确留项；这些安排不能被写成已经实施。

**结论要保留原资料的定义和比较条件。**

有些回答完成了主要动作，却在附加解释里自行补入条件：把未说明的纯度百分数当成摩尔纯度，把未明确绝压或表压的数字直接写成物理压力比。这样的补充同样会改变判断。

本版在推导规则中补充量定义和基准核对。百分数要说明对应的量、分子分母及基准；压力差与绝压比各自按适用条件计算。资料没有给出的定义留在实际结果中作为待核项，已有阈值和比较要求继续保留。交付复核同时检查这些附加结论，以及动作、状态和后续交接是否与证据一致。

设备审查还要把结果与判断条件成对交回。例如，两侧实际压降需要各自的允许限额；节能改造中新增的用电设备需要确认身份和进出口状态。限额或设备资料缺失时，指出具体缺口，不用一个实际数值或电耗数字代替适用性判断。

**经验整理要落到具体内容和维护位置。**

此前的经验流程已经区分临时收件与正式采用，但实际任务中仍会遗漏具体摘要、把审核意见混入已确认原文，或者完成了分类，却没有交出可执行的修改方案。

这一机制参考了几类外部记忆研究。[Reflexion](https://papers.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)把任务反馈整理成下一次尝试可读的文字反思；[ExpeL](https://arxiv.org/abs/2308.10144)从多次经历提炼文字经验，并在后续任务中调用经验、检索相似成功经历；[ACE](https://arxiv.org/abs/2510.04618)讨论了反复重写上下文导致细节丢失的问题，采用结构化增量更新维护经验。对本库有用的是这些思路：保留实际反馈和适用条件，在原有位置做有依据的局部修改，而不是把每次总结不断追加成通用规则。下面的收件、核查和版本流程是本库的具体落实，不代表复现了论文中的完整系统或性能。

本版补齐了当次交付要求。提醒应展示真实候选摘要、适用范围和投稿入口；内容确认与公开授权分别核对，已有有效授权在其范围内沿用。思想原则如要实质改写，先展示新版内容，再进行相应确认与审核。脚本和文件处理的成果也可沿同一入口整理，不只覆盖模型任务。

正式批次整理还要查现行规则和实际代码。我们补充了从判断用途到已有实现的检索路径，要求读取当前定义，安全执行可用的正反例检查，再给出具体修改位置和最小方案。原规则已经覆盖的，就说明不改的依据；找不到归属或缺少必要证据的，明确保留未完成部分。收件检查通过、文字总结和预期结果，都不能替代这些技术核查。

这延续了[前一轮经验维护改造](Agent工作流更新_2026-09-12.md)的方向：让有依据的经验进入适用位置，并保留版本与回退。相关研究用于解释设计选择，模型参数保持固定，临时经验仍不会自动进入正式规则或默认检索。

知识增补的规则也与这一流程衔接：先看资料能解决什么问题，再按结论和适用条件与现有内容比较。重复内容引用已有位置，新增内容以能够清楚解释的完整知识块保留。普通说明性知识检查内容与来源；可执行方法、经验规则和任务行为的改变，再接受相应验证。这样可以减少重复和零碎条目，也避免把每次阅读都变成完整的任务晋级测试。

**文字清单也要核对采购边界。**

另一个遗漏出现在设备与费用的衔接：物理设备数量可能被直接当作采购项目数量，没有核对成套包已经包含哪些部件。

本版让仅有文字清单的任务也能进入现有费用映射方法，先整理物理候选、成套范围和待核项。没有完整数据时可以生成明确标注的费用方法草案；实际计算前继续检查设备覆盖、价格来源、采购范围和费用分类。重复计费或来源错配未解决时，对应计算保持阻断，不填写猜测价格。

这些修改同时涉及提示规则和可执行工具。程序检查用于验证接口和脚本行为，助手任务复测检查真实调用、返回记录与交付物；两者的范围分别记录。规则存在不等于每次都能触发，具体工程任务仍需依据当前输入、目标软件版本和实际交付文件验收。本次维护没有运行商业 Aspen、EDR 或 SW6 项目模型。
