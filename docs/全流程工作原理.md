# 从资料到全流程

本工作库把“流程为什么这样安排”和“软件具体怎样输入”分开处理。前者由化工专家
和流程工作流负责，后者由操作脚本负责；知识图谱提供适用的方法，设备程序提供
可以复算的实施约束。它们最终都回到同一个项目的设计基准、当前决定和结果记录。

## 先理解任务，再决定从哪里继续

拿到文本时，先提取原料、产品、处理量、反应与分离路线、物性、运行条件和验收
要求，并区分哪些是用户指定、哪些是资料提供、哪些尚需推导。已有项目先读取
最新变更表和模型状态，不用旧报告撤回已经接受的修改，也不重开已经核实的
动力学。这个阶段形成可实施的设计合同，而不是急着输入几十张软件卡片。

专家层先检查全局：每个单元为什么存在、物料为什么按这个顺序走、组分最终去了
哪里，循环有没有积累和必要排放，热量和压力由什么设备提供。方案先满足不能
互相抵消的物理与工程条件，再在同一基准上比较能耗、复杂度和成本。求解收敛
是软件结果之一，并不回答流程是不是合理。

## 用简单骨架暴露全局问题

从零建模且允许简化时，先搭出覆盖全部进料、产品、废物流及主要循环的骨架。
暂用的反应或分离模块必须说明代表哪项物理任务、使用哪些有来源的转化或分配
数据。没有依据的比例不能为“先跑通”随意填入；用户要求严格动力学或物理分离时，
骨架只是经允许的初始化工具，不是交付替代品。

骨架的价值是较早发现规模、连接、组分去向、压力层级和循环初值的问题。初步负荷
一旦可用，就执行设备初筛，检查有没有明显的工况或能力矛盾；不等最终模型做完才
发现设备安排需要重来。此时计算会保留初步性质，不提前要求厂家最终型号。

## 把强耦合问题切成可核验的岛

从最新骨架导出岛入口，冻结流量、组成、温压、相态及产品义务，再在这个边界内
严化反应或分离。反应模型逐项核对原始动力学、单位换算、卡片或USER参数；
塔先获得适用方法下的基准，再做敏感性和在线目标控制。热泵岛先恢复原塔产品，
才比较压缩和换热条件。

岛不是随意把所有循环剪掉。共同决定结果的溶剂回收、热耦合或局部循环应留在
能够解释的边界内。每个岛记录自己的入口、方法、允许调节变量、目标和检查结果，
因此一个局部优化点不能混用另一版入口，也不能靠放宽产品或精度获得表面优势。

## 岛内计算先明确问题，再选择求解工具

进入岛内设计时，先分清目标。只想知道某板温度、某股焓值，先读同次有效结果；
需要按进料实时算补料或采出，才建立 Calculator。计算器读取的量必须已经由
本轮上游产生，写入的量必须在下游使用前准备好；依赖循环的关系纳入收敛顺序，
并避免与 Design Spec 同时争用一个操纵变量。

当响应未知时，用原生 Sensitivity 找可行窗口；已有同版有效区间时直接复用，
不重复扫描。随后用 Design Spec/Vary 使有真实自由度的目标闭合。“至少达到”
作为约束检查，不为了凑一个等式把已合格的模型推到不合理边界。若要联合调整
多个连续参数找最低能耗，则在可行基准上评估原生 Optimization，明确目标和
产品、压力、温度、设备限制。每个外层点都重新解内层质量控制，才能比较结果。

台数、进料板、流程分支等离散选择在外层比较，各固定方案内部仍采用适用的
原生工具。外部脚本可以负责批量建卡、启动、取表和方案编排，不默认代替原生
求解器。只有具体适用性或能力缺口才支持外部数值替代，缺少一个 MCP 快捷方法
本身不够。目标、边界、对象、执行顺序和结果一起进入工程记录；详见
[工具选择和插入时机](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/references/aspen_builtin_solve_fit_tools.md)。

## 图谱在做决定前介入，设备在有工况时介入

图谱按系统原则、机制、计算方法和来源细节逐层查询。例如评估高品位热源使用时，
先看能否减少本身的负荷、回收过程热和匹配温位，再查适用的预热或再压缩方法，
最后读取计算所需的具体关联式与条件。向量检索只是定位工具，命中相似内容后还
必须判断是否适用于当前介质、相态、温压和任务要求。

设备程序接收同一候选的工况，把单位归一后先完成可闭合的公式链，再检查设备型式。
报告中的一个模拟块未必对应一台实体设备；清单须说明这个对应关系，也不能把
逻辑混合或分流节点凭空变成独立设备。程序返回的计算、公式、适用规则和缺口与
来源一起保存，让工艺层知道问题究竟是参数错误、真实能力限制，还是目录和证据
暂不完整。

有来源的单机换热面积限制可以支持串联分段候选，但每段入口与温差改变后要重算
面积和压降，不能简单平均分配。压缩机分级要考虑级间损失、冷却及排气状态；
并联塔按各支路负荷重新核对分离与水力学，不能按台数削减每列分离级数。选择
候选时还要保留简单可行基准，不因目录评分略差就增加设备。

## 一次接回一个岛，再看全局是否仍成立

岛内结果通过相应范围的检查后，保留当前可回退版本，逐个接回母流程。接回改变
了循环与上下游条件，就以新导出重算相关设备、控制、热量和压力；岛内旧结果
只作为对照，不能继续给新版本背书。若接回失败，先根据本次诊断区分连接、
物性、库存、压力或数值问题，不同时改多个未知因素。

设备反馈是这一循环的一部分：先记录选择修改的依据，再真正修改流程、运行、
重新导出并检查。反馈程序输出的候选和“需要复算”列表不是已经实施的流程，
文件哈希也只是把结果与对象对应起来，不证明模型满足工程条件。

## 阶段入口怎样减少漏调用

专业Skill在路线确定、骨架出负荷、岛内设计、接回、工况变化及交付时，必须按
[阶段调用规则](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/DESIGN_STAGE_ROUTING.md)
进入实际查询与计算。这个入口调用原有知识和设备后台，返回请求及响应、当前
身份、结果和待办项。它不读取一条“已检查”的文字就放行，也不会因为一台设备
失败而删除其他设备的有效计算。

入口解决的是“有没有真正调用、算了什么、还有什么未闭合”。主流程仍需阅读
检索结果、审查来源适用性、确认设备清单覆盖范围，并完成真正的软件计算。
程序最多报告模块检查执行情况，不自动授予工程通过。最终验收继续使用原有
唯一检查实现；过程记录也不能用自报状态替代它。

## 最后交付的是同版成果和明确的证据范围

全流程先核对产品、守恒、循环、控制、设备能力与公用工程，再对精确交付文件
执行对应的软件验收。Aspen汇总按实际版本的完整表头读取，所有错误警告为零，
同时检查原始运行历史；最终路径文件还要无编辑复开运行。不同副本的好结果
不能拼在一起组成“通过”。

报告、PFD、设备清单和费用随同一版结果更新。缺少厂家或机械证据时说明具体
尚未验证的范围，不抹掉已有可靠计算，也不把初步设计写成最终认证。完成后询问
使用者是否还需要调整；明确确认当前任务结束后，才另行审查可共享的原则和
数据规律。普通查询不会修改规则库。

这条流程是完整任务的主线，不是所有问题的强制长度。单塔优化、公式复核、
模板生成和文字排版分别从所需模块进入；各模块的自然语言工作过程与文件入口
见[模块说明](模块说明.md)，实际运行命令见[使用手册](使用手册.md)。
