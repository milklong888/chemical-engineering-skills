# 源码、数据与运行边界

## 原工程与本发行的关系

这套技能集保留19个专业分工，并把原设备程序、知识库和Aspen工具接口接到同一
无界面调用层。通用计算不因入口简化而改成文字说明；项目数值不因代码被复用而
成为新项目的默认输入。历史原件、公开参数化代码和实际运行数据分别记录身份。

设备后台以原2.4.0工程为来源。源身份在
[原始身份目录](../backends/equipment/origin/)，当前源与运行资产的清单在
[后台说明](../backends/equipment/README.md)中说明。原17族计算、参数包、型号
层级及规则继续由同一程序负责；新增统一入口不重复实现选型算法。

## 按需调用的计算与测试资产

| 资产 | 作用与保全方式 |
| --- | --- |
| Aspen公共运行与监督器 | 会话、运行、保存和导出仍使用原操作模块；Windows虚拟环境的工作进程身份单独核对，超时只处置有归属的进程。 |
| 单塔与并联塔水力学脚本 | 原计算函数保留，改由显式配置提供源剖面、单位、物性、几何和适用限制。手算初筛与软件/厂家评级分开。 |
| 两段流程生成器 | 22个原函数名保留；项目组分、卡片和报告常量由哈希绑定的项目profile提供。当前生成候选与受控操作交接，不自动运行Aspen。 |
| 化工专家校验与记忆伴随文件安装器 | 提供既有体系结构检查和伴随文件安装；安装前做全量冲突检查。它们不是自动学习的后台服务。 |
| 原学习资格、候选和运行回归 | 保留原测试断言；需要私有工程证据的检查要求明确提供证据profile，未提供则标为跳过，不伪造工程正例。 |
| 原文件操作经验 | APWZ解包边界、备份身份、标签和保存复开经验放在公共操作模块的按需说明；历史放宽验收不成为现行规则。 |

各脚本的具体路径见[文件索引](文件索引.md)。塔和分段脚本保留自己的
`SOURCE_PRESERVATION`或配置合同；测试通过证明程序行为，不证明任一实际装置
已完成设计。

## 知识及标准数据

[知识清单](../knowledge/manifest.json)核对包内节点、来源定位及查询投影。
查询保留6,873个原节点身份；其中23个待核正文不进入检索矩阵，其余6,850个
构成768维哈希特征索引。这是本地检索算法，不是重新训练的化工大模型。

标准数据库包含24,887条标准记录、1,844条图记录、24个表数据集声明和14个图
数据集声明。图记录可能是结构化图义或提取事实，并不统一等于已经可计算的曲线。
目前原管路消费者使用的限定集合为12条PN记录及5,620条尺寸/重量记录；其余
数据仍按本条记录的适用范围、QA和复用状态使用。完整未处理资料不能因有数据库
就被称为已经全部数字化。

数据库以压缩SQLite随包，在内存核验和加载。原数据库身份、投影身份及被去除
字段的原因分别保留；不能用新投影的hash冒充原始数据hash。

## 不进入默认执行的资产

原教材/商业帮助整页正文、扫描PDF、私人项目模型、报告、历史试算和专用成本
数表不随公开包分发。对应原件没有因本发行而删除。来源位置和缺口状态保留，
但目标电脑查询不会暗中访问旧电脑。

资料重建、OCR、表格审计等维护源码与当前运行后台分开。
[原维护脚本处置清单](../knowledge/script_source_manifest.json)逐项记录原身份、
公开位置或私有保留理由。需要原PDF、Word、旧项目表格或额外OCR依赖的维护
工具，不计入开箱即用的离线运行范围。仅改为source-build-only标签不使其中
项目数据获得公开或通用复用资格。

## 离线依赖与商业软件

原Aspen MCP工具的源码及许可证保留在
[工具包目录](../vendor/aspen-mcp-toolkit/)。70个固定运行依赖和1个NumPy扩展
从随包轮子离线安装，目标是CPython 3.14、Windows AMD64。源维护或报告生成
工具可能另需python-docx、PDF/OCR或排版工具；不把这71个轮子说成所有历史脚本
的无限依赖闭包。

Python解释器、Aspen、EDR、SW6及许可由使用环境提供。MCP是通信方式，既不
提供商业软件许可，也不把云端推理模型变成离线模型。设备与知识工具可以本地
运行；模型宿主和真实工程软件分别配置、分别验证。
