# 0.4.14：模块规范化、主库与本机部署

按用户直接维护要求完成三遍规划复核：先核来源和唯一owner，再核接口/依赖/未实现
范围，最后核发布、安装保留与回退。来源固定在经验库
`1e0a6c7a50b2233de02fb214f258444b1e0d33ab`，主库基线为
`4b0cdbcddffc2b5c2fe11e913ca120f0748a138b`。这是工具与规则组织维护，不是工程案例晋升。

12个维护单元和23份提案在`runtime/module_catalog.json`逐项登记。操作辅助归operations，
四项EDR诊断归EDR，收敛观测归error-repair；解析器复用原owner。已有双效方法以专门
Skill补入公共工作库，因此活动模块由19增至20。来源、许可、变换及未实现项保留。

专家CLI增加`module_catalog`和`module_check`，现有专家MCP提供同名入口。九项
Dynamics/EDR操作经固定允许表调用同一实现；任意模块路径、外部调用计划和归档代码
不会被这些入口执行。独立命令行与stdio入口仍可使用。

以下内容没有被改写为已实现：原生Dynamics控制、操作图位置诊断、自动1061诊断、
通用原生依赖解析、方法预算执行器。两组受隔离的归档代码仅有来源元数据，排除默认
工具及安装；材料库架构和历史文本测试保留原状态。重复P0编号按来源限定，旧代理
型号条款服从当前任务模型选择规则。

导入的文档/双效方法保留CC BY 4.0范围及作者来源，原代码保持相应许可；资料页、
客户模型、原始日志和私人设置不在发行树。SVG只纳入声明式本地图件，验证器拒绝
活动节点、事件和外部href；官方URL中的home路径段不再误判成机器目录，真正机器目录
继续拒绝。

发布使用既有stage/seal/verify工具。安装器新增可重复的`--only <精确manifest路径>`，
先验证完整发行版，再对清单选中的可安装文件执行原有冲突备份、原子写入与回读。
本机更新先比较基线、当前本机和新源；有本机扩展的正文按三方合并另存回执，其余
用限定清单安装。未列文件保持原身份，不把公开源整树覆盖本机。

验证支持离线工具、合同、真实stdio及安装行为；不声称运行过Aspen/Dynamics/EDR或
任何设备通过。最终执行记录和本机回退文件保存在维护工作区，公开源不携带私人路径。

整库回归还修复一处0.4.13遗留身份绑定：知识构建器的严格owner指纹仍对应0.4.10。
经独立核对，当前正文与0.4.13基线逐字节相同，学习隔离及正式零表/精度/复开要求
保持；本次仅重绑该指纹并更新知识manifest中的对应文件身份，不更改严格正文。
