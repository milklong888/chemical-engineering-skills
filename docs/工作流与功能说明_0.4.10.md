# 从设计资料到可核验的 Aspen 全流程

这套工作库将工艺判断、Aspen 建模、知识检索和设备计算组织成一套分层工作方法。主线是：先明确设计依据，让简化流程实际运行，再逐模块细化，通过设备计算反查工况与结构，最后接回整厂并核验交付文件。19 个 Skill 分担具体任务，主助手负责选择入口、整合结果和最终交付。

## 第一层：专家规划——明确依据，检查流程是否合理

规划从当前设计要求开始。助手读取任务书、论文条件、已有模型及已确认的变更，确定进料与产能、产品指标、反应网络、反应条件与程度、分离目标，以及用户指定的方法。原文事实、计算推导、设计候选与待核条件分别保留，后续模块在同一份基准上工作。已有工程优先使用当前有效决定，继续完成尚未解决的部分。

随后沿每种组分的去向安排模块链。每个模块说明它为什么存在、入口需要什么状态、出口要发生什么变化，以及下游由谁接收。循环回收、惰性吹扫、补料、放空、废液和固体终端都需要落在明确节点上。这个检查能发现“单个单元看似成立，连起来却不合理”的问题，例如没有去向的副产物、没有排放路径的惰性循环、重复压缩后节流，或不必要的混合后再分离。

热力学方法是逐模块检查项。先判断组分、相态、温压和可能出现的电解质、缔合、液液分相或共沸行为，再核方法及参数是否适用。内置图谱提供原理和操作联系；存在方法适用性疑问时，优先查当前工作区登记的外置专著，再核对软件中的实际方法与输入。

热量和压力在这一阶段一并安排。下游需要的温压与相态，应通过真实的换热、加热冷却、泵、压缩或降压设备实现，并给设备压降留下计算位置。节约高品位热源时，先检查能否降低本身负荷，再考虑过程预热和热回收、相容的热源与热汇温位或流程顺序重排，随后评价适用的再压缩或热泵；压缩功、温差、排温和启动备用条件纳入同一方案比较。

完整流程的同一版模块链接受五份独立审查，审查者都需要检查整条链的模块、物流组成、热力学依据和热压配套。主助手逐项处理分歧，补充依据或明确缺口。规定的是五份独立判断，具体并发方式取决于宿主资源。

**这一层留下什么：**设计基准、模块—物流账、物性与热压依据、变更记录，以及五份审查的处理结果。[专家入口](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/SKILL.md) · [全流程规划方法](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/references/fullflow_generation_workflow.md)

## 第二层：简化全流程——运行骨架，取得循环初值

规划明确后，在允许简化的范围内，用 RStoic 表示反应、SEP 表示分离，先建立完整物料路径。反应转化程度和分离分率仍应来自资料、推导或明确标注的候选；简化是为了分开求解难度，而不是自由填数。换热器、加热冷却器、泵、压缩机和实际循环按其物理职责保留。

骨架由 Aspen 实际运行。有循环时，助手从当前结果读取其流量、组成、温压和相态，为后续模块细化提供边界与初值；没有循环时，记录无循环依据及对应检查不适用。骨架运行后，再安排三份独立复核，按同次导出机械复述实际块、物流、关键参数和热力学依据，检查图、文字与模型是否一致。

初值只是后续计算的起点。严格模块替换、工况改变或循环接回后，需要重新求解并更新受影响结果；规划图和输入文件本身不能证明骨架已经运行。

**这一层留下什么：**可追溯的简化模型、同次结果与日志、循环初值和三份导出复核。[流程组织](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/SKILL.md) · [软件操作](../plugins/chemical-engineering-skills/skills/aspen-plus-operations/SKILL.md)

## 第三层：模块细化与回装——保持原接口，逐个替换

### 把计算复杂度分到单个模块

从最新骨架中取出一个反应、分离或能量模块，固定入口和目标，交给相应专业 Skill 建模。这里的“岛”指单独计算和验证的功能模块，并不意味着重新划分工艺路线。相应方法读取完整后才执行，原有脚本按当前组分、单位、来源和软件版本适配。

普通精馏先复制母流程进料到独立子模板，使用 DSTWU 取得有依据的初始板数，再在塔岛建立 RadFrac。正式严格塔保留有效的塔内 Design Spec/Vary，由纯度或回收率目标求解回流比、D/F 等获准操作量；先在初始板数下比较进料板，再调整总板数，并在每个候选上重新求目标、复核进料位置和热负荷。特殊分离不符合 DSTWU 假设时，说明原因并按获准严格路线处理。回装的是带塔内设计规定的严格塔，临时进料和简捷塔留在子模板中。

反应器细化需要连接来源速率式、参数单位、Aspen 输入基准和导出结果；换热、热泵、压力与循环问题则进入各自的专业方法。不同模块的必要检查由原专业 Skill 负责，完整流程主线负责边界与交接。

### 原生工具在何时加入

工具由工程问题决定，图中的选项是可单独或组合使用的分支。

| 当前问题 | 适用入口 | 在流程中的时机 |
| --- | --- | --- |
| 读取已有流量、焓、温度或状态 | 当前结果、只读查询 | 先读同次结果，避免为查值新建控制对象 |
| 一个明确关系需要随工况更新 | Calculator | 在依赖该关系的设备首次计算前建立；每轮取得当前输入后执行 |
| 反求某个操作量，使产品或过程达到目标 | Design Spec/Vary | 确认自由度、目标与边界后建立；塔内规格使用塔内设计规定 |
| 观察变量变化引起的响应、寻找可行区间 | Sensitivity | 有可运行基线后进行；说明哪些量固定、哪些需要联动 |
| 在约束下寻找更优设计 | Optimization | 已明确目标方向、变量、边界和可比产品基准后进行 |

例如改变热泵压缩压力时，如果比较目标是相同产品条件下的能耗，内层质量设计规定也需要重新求解。固定旧回流比得到的曲线，只能按固定控制条件解释。Calculator 与 Design Spec 也不能同时写入同一操纵量。

### 设备计算怎样反查模块

一个模块细化完成后，将其最后一次运行导出与岛内全部实体设备对应，交给设备后台。程序先统一位号、单位、压力基准和设备用途，计算当前可以闭合的参数，再进行初步型式及能力校核。每项结果保留输入、公式、标准或规则、计算状态和待补证据。

设备反馈需要区分原因。真实单机能力受限时，研究改变结构、分段、分级或并联；即使未超限，也可在同一产品与设计基准下比较有证据的全系统性能、能耗、投资或控制收益。目录没有型号或关键资料缺失时，先保留可用初选并补证据。增加台数或复杂度需要可归因的限制或经比较成立的系统收益。

| 受限情况 | 需要研究的调整 | 修改后重新检查 |
| --- | --- | --- |
| 换热器单壳尺度或面积达到适用限制 | 分段串联或其他适用型式；流量瓶颈另行判断 | 逐段温态、传热温差、两侧压降及累计损失 |
| 泵扬程或压缩机压比、排温受限 | 串联、分级及适用的中间处理 | 级间状态、功率、压降和设备工作范围 |
| 泵或压缩机吞吐量受限 | 有依据的并联与支路分配 | 支路流量、共同边界压力和控制方式 |
| 塔水力处理量受限 | 并联及进料分配 | 各塔负荷、内件能力、产品规格和总流程 |
| 分离任务需要分段，或单壳高度受限 | 有依据的分段方案 | 新的分离职责、能耗、压力和接口 |

压降计算按设备与流动条件选择方法：管路需核长度、直径、局部阻力、物性与流态；换热器按冷热两侧和实际结构分别计算；塔内压降回到相应内件和水力学方法。串联后核累计损失，并联支路核共同边界和流量分配。具体公式及其适用边界见[后台计算说明](后台运行与计算说明.md)，不得用一个通用管路公式替代所有设备压降。

选定变化后，专业模块修改真实模型，重新运行该岛，并把新结果交回设备检查。每个模块通过适用检查后，按原接口逐个接回；母流程入口和循环可能改变其负荷，因此全部接回后仍按整厂最新导出复查设备。后台支持 17 类，检查范围以实际设备清单为准，未知家族或遗漏位号单列为覆盖缺口。

**这一层留下什么：**严格模块、原生规格与计算记录、设备计算包、调整与复算依据，以及接回后的整厂结果。[设备后台](../plugins/chemical-engineering-skills/skills/equipment-design-app/SKILL.md) · [反馈与回装规则](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/PROCESS_EQUIPMENT_FEEDBACK.md)

## 第四层：软件执行与交付——核对同一文件的实际结果

软件操作层按已明确的设计与允许改动执行。脚本、COM 或可选 MCP 负责对象与卡片操作、运行安排、保存和结果提取；过程结果由 Aspen 原生模块、物性方法和求解器计算。运行失败时，故障模块根据同次 Control Panel、历史和流股结果诊断，再在受保护候选上修改、复跑并核对影响。

正式交付必须检查精确交付路径的文件。该文件在没有进一步模型编辑的情况下复开运行，经核实版本表头中的 Terminal Errors、Severe Errors、Errors、Warnings 在全部实际列上都为零；同次 Control Panel 消息和原始 `.his` 也没有实际错误或警告行。未知格式、缺行缺列和相互矛盾的结果保留为未通过。

默认及已有求解容差的数值与默认／显式卡片状态保持不变，使用修改前后同版本导出核对。产品流量、纯度、回收率、衡算、设备及目标版本兼容性分别取证。若涉及 EDR、SW6 或厂家结论，还需要同设备的相应证据。

**这一层留下什么：**交付模型、精确文件身份、复开运行记录、产品与设备结果、报告或流程图，以及明确的未闭合项。[公共操作与验收](../plugins/chemical-engineering-skills/skills/aspen-plus-operations/SKILL.md) · [故障处理](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-error-repair/SKILL.md)

## 第五层：任务结束后的自进化——分别改进原则与数据规律

用户明确结束当前任务后，助手再整理本轮经验。提示词层提炼能改变工程判断和工作顺序的宏观原则，例如先核全局物料去向，再做局部优化；具体数值、设备细节和局部操作记录保留在相应下层。数据规律则需要可比较的样本、基线和结果，检验某种初值、控制关系或调参顺序是否改善收敛或设计表现。

新经验先核对来源与适用范围，再通过对照、边界或反例检查，交给已有的专业负责人维护，保留版本和回退依据。没有可靠增量时可以不修改。当前任务内的临时调整先写项目记录；用户局部放宽验收的案例及其后代不进入共享学习。

这里的自进化是知识、提示词和可复用方法的维护流程，并不改变基础模型权重，也不会在安装后自动上传工程资料。

## 右侧两个模块的来源与组织

**内置图谱**与专业 Skill 紧密配合。随包知识包括化工原理的思想、原理和方法卡，孙兰义 Aspen 图谱的通用方法，以及 Aspen V10 细节与章节导航；另有经采纳的反应、分离控制、热力学和能量系统知识块。来源身份和内容状态分别记录。检索先按任务范围定位，再按需要读取完整节点、关联和来源；当前软件操作仍核对目标版本。公开包的实际内容和检索方式见[知识库说明](../knowledge/README.md)。

**外置专著图谱**单独登记，以专著与工程手册为来源，按章节、主题、知识单元和原页证据组织。公式关联变量、单位与适用条件，表格保留表头和续表关系，曲线记录坐标、范围和读取方法。它在方法存疑时按需返回依据，完整原书不属于公开包的必备内容，查阅也不自动改写内置图谱。

**设备后台**按设备族组织程序、标准事实和适用规则，保留从工况、参数推导到初步选型和反馈的计算链。它的实现来源和知识组织来源均可追溯，所需运行资产已随包提供，不要求使用者另装来源仓库。具体来源、数据清单和许可见[来源与许可](来源与许可.md)；实现位置见[文件索引](文件索引.md)。

## 专业模块、运行环境与验证范围

19 个模块的详细职责、接手条件和主要文件集中在[模块说明](模块说明.md)。单塔、设备、模板、费用或文档任务直接进入相应入口，只完成自身适用步骤。完整流程生成才采用上述五份源审查、骨架实跑与三份导出复核。

工作流选择、知识查询和阶段检查已经通过统一命令行及可选 MCP 接入；返回的方法或回执用于安排操作，实际 Aspen 建卡与求解需要对应软件环境。部分旧脚本属于需项目适配的模板，原生 Sensitivity 的目标接口资格核验仍待完成，详见[建模入口与脚本边界](modeling_start_here.md)。SW6 字段传递需要已验证的本地映射，费用分析需要有效经济包或经审核的价格来源。

发行包提供离线知识、设备后台和固定依赖；CPython、合法工程软件及当前项目资料由目标环境提供。程序、结构和助手任务的验证记录与真实工程模型的验收分别保留，具体见[使用手册](使用手册.md)、[外部依赖](外部依赖.md)与[0.4.10 验证记录](验证记录_0.4.10.md)。
