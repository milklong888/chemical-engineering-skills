# 模块说明

这套产品把化工设计中的判断、建模、计算和验证分给 19 个专业 Skill。化工专家先明确要解决的问题、指定方法和判断依据，流程模块组织反应、分离、循环和公用工程，设备模块检查实际设备能否承担这些要求，公共操作层把已确定的方案写入软件并取得结果。以下按职责说明每个模块怎样接手任务、调用已有方法、核对结果并交回主线；单一问题只进入相关一段，不必同时加载全部内容。

本产品自带原知识节点、离线检索、设备算法、结构化标准事实、压力与流程反馈、统一命令及可选 MCP，不要求另行取得其他 RAG 或设备仓库。Aspen Plus、EDR、SW6 及其许可、当前工程模型、厂家资料和未随包原文由使用者提供。合成示例用于理解输入和检查程序，不是实际装置或工程认证。具体文件和维护资产分别见[文件索引](文件索引.md)与[新增后台文件索引](新增后台文件索引.md)。

## 一、宏观判断

### 1. 化工专家：chemical-engineering-expert

接到工艺、设备、计算或报告任务后，化工专家先读取用户要求和当前项目依据，明确系统边界、进料与产品基准、指定方法、禁止替代及验收条件。它先判断问题位于哪一层：比较流程安排时查常识知识库的系统观和原理，进入尺寸或参数计算时再下钻到方法、公式和来源位置。资料没有直接写出某个数值时，继续检查已有导出、单位换算、计量关系和物料能量衡算，把可推导的结果与真正缺少的输入分开。

安排专业工作前，它沿整个流程检查反应与物性、相态、组分去向、压力和热量路径、循环排放及控制条件。先判断不可用评分补偿的物理与安全约束，再在相同产量、品质和边界下比较方案。降低高品位公用工程时，先考虑减少本身负荷和过程预热、热回收，再评价适用的再压缩或热泵，把压缩功、温差、启动备用和控制代价算回系统。随后将具体工作交给专业模块，收到结果后复核上下游影响，并交回带来源和状态的结论。检索命中、流程收敛或设备有候选都不能单独证明设计优良。

入口：[化工专家技能](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/SKILL.md)。宏观判断、设备反馈和验收采用相应专题说明；只有需要计算或验证时，才继续读取下层方法与原始资料。

相关文件：判断整体方案时读[宏观设计质量](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/MACRO_DESIGN_QUALITY.md)；区分事实与推导时读[推理协议](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/REASONING_PROTOCOL.md)；设备结果需要回到流程时读[流程—设备反馈](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/PROCESS_EQUIPMENT_FEEDBACK.md)；准备验收或整理方法时读[严格验收与学习边界](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/STRICT_ACCEPTANCE_AND_LEARNING.md)。

## 二、流程建模与软件操作

### 2. 文档驱动流程：aspen-document-driven-flowsheet

这个模块接收任务书、论文或工程报告，以及已有模型、当前变更表和运行结果。它先把路线、反应、分离目标、物性及进料产品要求整理成可追溯台账，再确定项目已经走到哪一步。已有项目从当前有效阶段继续；新项目只有在任务允许时才先建立物料衡算骨架，并明确临时反应或分离替代的身份。文档到骨架、严格单元和逐段接回是原有建模工作流，不是另加的一种自动求解能力。

实施时，动力学参数先走来源冻结，塔或溶剂回收交给塔系优化，热泵改造交给专用模块，复杂边界交给分段模块，卡片与文件动作交给公共操作层。严格单元在清楚的出入口条件下验证后逐个接回；失败时带同次日志、流股和规格状态转入故障处理。流程建立或负荷改变后，用同一候选的导出执行设备检查，将有依据且获准的变化落实到真实模型，更新循环、控制、热功负荷、产品和报告。最终向化工专家交回模型、阶段证据与未闭合项，不把临时骨架或局部收敛冒充严格交付。

入口：[文档驱动流程技能](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/SKILL.md)。提取源要求时读取来源协议，搭建或接回单元时读取流程方法，填写软件卡片时调用操作模块。

相关文件：[快速路由](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/references/quick_router.md)用于定位当前阶段；[来源与任务书协议](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/references/source_taskbook_and_gate_protocol.md)用于固定要求；[流程工作方法](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/references/aspen_workflow_playbooks.md)用于骨架和严格单元；需要复用操作框架时查[脚本模板目录](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/references/script_template_catalog.md)。

### 3. 分段流程：aspen-two-section-flowsheet

当流程连接过密、难以定位问题，或不同工程段需要分别验证时，分段模块先盘点现有模型、导出和有效分支，再按实际职责划分边界。反应列、溶剂循环、气体净化、产品中间体或公用工程都可能成为分段依据，位号相邻却不必属于同一段。每段说明自己的反应、分离、补料、循环和出口义务，每条跨段流股则明确流量与组成基准、温压、相态和去向。

边界确定后，它选择独立案例、局部单元岛或连接全流程中的合适形式，调用公共操作层创建和连接对象。局部结果先与本段合同比较，跨段流股再与接收段要求核对，合格后交回文档驱动模块逐段接回。临时种子不是已闭合循环，外部补料不能隐含为无代价内部物流。随包生成脚本通过当前项目的显式 profile 和哈希提供组分、分子量、工况及卡片，只产出候选输入和受控运行交接单；缺失读回保留未知，原不安全运行体只作审计文本，合成 profile 不代表实际流程。

入口：[分段流程技能](../plugins/chemical-engineering-skills/skills/aspen-two-section-flowsheet/SKILL.md)。先定义每段的反应、分离、循环、补料和产品职责，再由操作模块生成或连接软件对象。

相关文件：[build_two_section_corrected.py](../plugins/chemical-engineering-skills/skills/aspen-two-section-flowsheet/scripts/build_two_section_corrected.py)保留原两段生成、换算、流股读取和导出函数，通过有哈希的项目profile提供组分、数值与卡片；[PROFILE_CONTRACT.md](../plugins/chemical-engineering-skills/skills/aspen-two-section-flowsheet/scripts/PROFILE_CONTRACT.md)说明所需字段、单位、空输出目录和运行交接。当前入口只生成候选及公共操作层交接单，不会自动启动Aspen或把输入生成视作求解通过。合成profile仅供测试结构，真实项目profile不随包分发。

### 4. Aspen 公共操作：aspen-plus-operations

公共操作层接收上游已经确定的案例身份、操作目标、单位、允许修改范围和停止条件。它先从操作图谱选择已有路径，涉及脆弱卡片或枚举时检查使用者安装的对应版本帮助与实际导出，再在自己拥有的受保护会话中执行打开、组分物性设置、建块连流、写卡、运行、保存和导出。它不在执行过程中自行改路线或产品目标，也不接管用户无关的 Aspen 会话。

运行库管理会话、版本、单位和资源，外部监督器控制各阶段期限，证据解析器解释完整汇总表与同次原始历史。检查候选时复开指定文件采集证据；正式交付还要对复制到交付位置的精确文件无模型编辑地重新运行，再核对产品、守恒、设备和目标版本。返回时分别报告动作完成、求解干净、产品达标和交付状态。真实执行需要合法 Aspen 与相容的 Windows COM 环境；MCP 只是可选方式，缺行缺列、未知格式和矛盾日志不能补零，保存或成功短语不能替代验收。

入口：[Aspen 公共操作技能](../plugins/chemical-engineering-skills/skills/aspen-plus-operations/SKILL.md)。字段问题先查当前版本帮助；文件运行、历史解释和保存复开使用对应公共程序，不另写一套相互矛盾的验收逻辑。

相关文件：[aspen_runtime.py](../plugins/chemical-engineering-skills/skills/aspen-plus-operations/scripts/aspen_runtime.py)提供会话、单位和生命周期操作；[aspen_run_supervisor.py](../plugins/chemical-engineering-skills/skills/aspen-plus-operations/scripts/aspen_run_supervisor.py)控制外部工作进程的阶段超时；[aspen_evidence.py](../plugins/chemical-engineering-skills/skills/aspen-plus-operations/scripts/aspen_evidence.py)解释汇总和历史；不改模型的文件检查使用[aspen_clean_delivery_audit.py](../plugins/chemical-engineering-skills/skills/aspen-plus-operations/scripts/aspen_clean_delivery_audit.py)，仅检查 APW 保存与复开时使用[apw_saveas_reopen_check.py](../plugins/chemical-engineering-skills/skills/aspen-plus-operations/scripts/apw_saveas_reopen_check.py)。这些程序的结果仍按各自阶段解释。

### 5. 组分模板：aspen-plus-template

只需要组分库和文件模板、尚未开始完整流程时，这个模块从有来源的组件 CSV 入手，核对组分 ID、CAS、名称、数据库身份、物性要求、单位和目标版本。某个本地目录没有找到组分时，会继续检查可用数据库与帮助，而不是用相似化学品替换；确实只能占位的条目单独标明，不能算作已验证组分。

身份冻结后，现有生成器准备文本输入，通过公共运行层让 Aspen 自己转换并导出归档，再重新打开精确模板，将导出的 COMPONENTS 与预期清单比较，记录缺项、多项、占位和文件身份，交回后续流程建模。只有组分而没有单元的模板按组分及文件往返检查，不人为添加生产流程；用户要求的测试流也只是一份测试输入。实际转换仍需 Aspen／COM，组分正确不证明反应、分离或设备已经设计完成。

入口：[组分模板技能](../plugins/chemical-engineering-skills/skills/aspen-plus-template/SKILL.md)。准备模板前核对组件 CSV 合同；生成后检查实际导出的 COMPONENTS，而不是只看文件存在。

相关文件：[create_aspen_template.py](../plugins/chemical-engineering-skills/skills/aspen-plus-template/scripts/create_aspen_template.py)读取组件 CSV，调用软件转换并执行组分往返核对。运行前先按入口说明准备字段和输出目录。

### 6. 流程故障处理：aspen-flowsheet-error-repair

故障处理接手的是当前失败候选、允许改动和同次诊断证据。它先区分资源启动、输入卡片、物性相态、循环控制、产品能力和文件身份问题，再沿相关流股重建物理职责。明确问题所在后，才测试有依据的初值、阻尼、迭代或结构调整，不先堆求解器参数，也不以降低精度换取干净状态。

每轮在受保护候选上实施一类可解释的修改，由公共操作层复跑并返回新消息，再判断原故障是否消除、是否暴露下一问题，或当前假设是否无效。循环库存、规模和错误根进入循环专用方法，塔规格进入塔优化，动力学常数回到当前来源冻结。影响工况或结构的修复还要更新下游流股、质量控制、负荷及设备，再向流程主线交回改卡、原新诊断和复算证据。局部修复不等于全流程验收，外部出口数值不能写入后冒充 Aspen 原生求解。

入口：[流程故障处理技能](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-error-repair/SKILL.md)。先重建实际物理职责和流股路径，再进入相态、规格、循环或数值控制的专项方法。

相关文件：相态、规格及外部再沸器问题读[故障处理工作流](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-error-repair/references/repair_workflow.md)；循环库存、规模、根选择和控制顺序问题读[循环与规模控制](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-error-repair/references/recycle_scale_control_repair.md)。

## 三、分离与能量安排

### 7. 塔系优化：aspen-tower-optimization-workflow

塔系优化从当前进料、物性相态、分离机理、压力、产品和回收率要求出发，先确定初始化路线。普通关键组分精馏可在适用时使用简捷模型，用户指定的 DSTWU 到 RadFrac 顺序必须保留；吸收、萃取、共沸或不满足简捷假设的任务则说明原因，采用获准的严格路线。初始化值来自当前来源和计算，不复制旧案例倍率。

得到收敛基线后，用有边界的敏感性了解响应，再建立实际运行的 Design Spec 与 Vary 配对。外层压力、结构或负荷改变时，内层回流和采出控制重新求解，只有容量、纯度和回收率可比的点才进入能耗或经济比较。塔岛通过后交回流程主线接回，并把当前负荷和几何交给塔设备设计及设备反馈，检查压降、水力学和实体能力。随包单塔及并联填料初筛保留原计算函数，但物料收敛、离线扫点或初步水力学不等于真实内件评级和最终塔设计。

入口与主要文件：[塔系优化技能](../plugins/chemical-engineering-skills/skills/aspen-tower-optimization-workflow/SKILL.md)给出初始化、基线、敏感性、规格控制和接回的顺序；包内[塔优化工作流](../plugins/chemical-engineering-skills/skills/aspen-tower-optimization-workflow/references/tower_optimization_workflow.md)进一步说明执行与比较方法。[单塔初筛](../plugins/chemical-engineering-skills/skills/aspen-tower-optimization-workflow/scripts/radfrac_packed_hydraulic_from_bkp.py)与[并联塔初筛](../plugins/chemical-engineering-skills/skills/aspen-tower-optimization-workflow/scripts/parallel_radfrac_packed_hydraulic_from_bkp.py)保留原计算函数，用显式配置给定源文件、剖面字段、单位、物性和适用限制，输出可追溯的填料水力学初步计算。配置结构见[水力学输入合同](../plugins/chemical-engineering-skills/skills/aspen-tower-optimization-workflow/scripts/packed_hydraulic_config.schema.json)。真实模型、软件许可和版本帮助仍由使用者提供；正式塔设备设计进入塔设计模块。

### 8. 蒸汽再压缩热泵精馏：aspen-heat-pump-distillation-replacement

热泵模块处理有明确产品职责的既有塔改造，不是所有热集成任务的默认入口。它先保存并运行未改动的塔；涉及母流程集成时，也检查实际所属流程段，取得进料、产品、回流、汽化、温压和热负荷基线，再在边界清楚的塔岛上改造。取消塔内冷凝与再沸的主供能后，将塔顶蒸汽经压缩送入外部换热器热侧，塔底液经受热闪蒸形成汽相返回与塔底产品，冷凝顶流经降压分流返回回流及馏出产品。

导出拓扑证明这些职责完整后，先调整有依据的塔内级数、进料或返回位置、回流分流和闪蒸条件，恢复原塔分离效果，再比较压缩压力、换热温差、压缩功和剩余外部公用工程。相态处理服从当前模型与设备依据，不自动添加过热器或抛光塔掩盖等效替换失败。塔岛合格后回到塔系与流程主线接回，重新检查循环、产品和设备。模板只说明结构与控制配对；真实结果需要 Aspen、可信物性和同案基线，不能预先承诺压缩一定节能。

入口：[热泵精馏替换技能](../plugins/chemical-engineering-skills/skills/aspen-heat-pump-distillation-replacement/SKILL.md)。先读替换工作流，再确定回路结构和控制；结构模板中的数值不自动成为当前项目条件。

相关文件：[替换工作流](../plugins/chemical-engineering-skills/skills/aspen-heat-pump-distillation-replacement/references/replacement_workflow.md)说明等效改造和验证次序；[空塔再压缩结构模板](../plugins/chemical-engineering-skills/skills/aspen-heat-pump-distillation-replacement/templates/empty_column_vrc_template.inp)帮助检查连接职责；[设计规格模式](../plugins/chemical-engineering-skills/skills/aspen-heat-pump-distillation-replacement/templates/design_spec_patterns.inp)用于理解受控目标与操纵变量的配对。模板不是已设计好的实际装置。

### 9. 压力路径与 PFD：aspen-pressure-pfd-delivery

这个模块在既有流程或塔系之上检查压力是否沿真实物理路径变化。它接收当前模型、流股结果、压力台账和允许压降约定，从新鲜进料与边界逐段核对：气体增压是否由压缩机承担，液体增压是否由泵承担，降压是否有合适设备，热块和反应器是否隐藏了未经授权的压力变化。具体压力、效率和特殊卡片数值须按当前来源及软件版本解释。

发现问题后，把设备和流股对应及修改理由交给流程主线，获准后由公共操作层更新重算，再核对实际导出的压力断点、块状态和循环。需要 PFD 或报告时，图文随这一版模型更新，特别检查种子流改为真实循环后有无残留旧流股和补料叙述；PDF 还需编译、渲染及关键标注核对。它交回压力证据和图文一致性，不以图上画了设备替代守恒与软件验收。实际图源、模型和排版环境由任务提供。

入口：[压力路径与 PFD 技能](../plugins/chemical-engineering-skills/skills/aspen-pressure-pfd-delivery/SKILL.md)。涉及压力时先检查流股来源与实际设备，再核对图文表达；软件执行使用公共操作模块。

相关文件：本模块的检查表集中在入口正文。具体 PFD 源图、报告生成器和项目压力台账由使用者提供，不随模块附带。

## 四、实体设备与详细校核

### 10. 设备应用接口：equipment-design-app

这个 Skill 调用本产品自带的无界面设备后台。接到人工参数或同案 Aspen 导出后，先读取实际能力、字段和目录合同，规范设备身份、单位、压力基准与物理服务，按设备族执行所有当前可闭合的确定性计算，把输入、公式、派生量和限制写入同一参数包，再进行型式与规格匹配。批量任务复用同一后台，但每项保留独立状态；局部字段问题不抹去其他可靠结果。

输入不足时保留已知参数、可算结果、最小缺项和有状态的初步型式。建议公式和筛选假设须显式披露，不覆盖同案值，也不升级为厂家终选；可选模型辅助只能在冻结上下文中提出登记的推导或受约束的缺项补充，再交回程序复算。流程反馈时，把同版工况、公式和真实限制交给反馈层，区分物理超界、单机限制、目录与证据缺口；有依据的调整仍须回主流程实施重算。手动及已有 JSON 路径不需 GUI、COM 或远程模型，初步型式也不等于厂家定型或全流程通过。

入口：[设备应用技能](../plugins/chemical-engineering-skills/skills/equipment-design-app/SKILL.md)。连接实际应用时，先读取其 capabilities/schema/catalog，再构造请求；不同程序版本不能仅凭字段相似而混用。

相关文件：[应用合同](../plugins/chemical-engineering-skills/skills/equipment-design-app/references/app_contract.md)规定请求、计算、受控辅助与输出边界。实际代码为[设备JSON后端](../backends/equipment/app/equipment_design_agent.py)，原算法、数据库投影及逐项身份见[后台说明](../backends/equipment/README.md)。合同不是计算实现的替代物，两者随包衔接。

### 11. 设备计算与选型审查：chemical-equipment-selection-audit

设备审查从当前报告、设备清单、已接受的流程导出和适用来源开始，先核对位号与软件块的真实对应，提取现有工况、组分、连接和卡片，排除其他模板中的介质、材料、产品及旧值，再逐台建立公式和输入台账。当前文件能取得或确定性推导的事实先自行闭合，不因缺少厂家报告就把所有参数写成待补。

计算时通过本产品设备后台取得登记公式和匹配结果，再按设备图谱及来源类别审查适用性。差异要回到原表、单位与公式独立重算，区分提取错误、基准差异、公式误用和真正缺终证。能够裁决的错误给出修正，仍缺 EDR、SW6 或厂家依据的结论明确保留边界。若任务包括改报告，就把裁决落实到具体段落和表格，检查正文覆盖及最新图文，向流程或设备主线交回计算台账、撤回项和补证要求；参数变化继续传回模型及下游复算，而不是只交标题骨架。

入口：[设备选型审查技能](../plugins/chemical-engineering-skills/skills/chemical-equipment-selection-audit/SKILL.md)。选择公式前确认设备职责、输入基准和适用域；遇到差异时依次核对原始单元格、单位、公式和来源。

相关文件：[审查任务示例](../plugins/chemical-engineering-skills/skills/chemical-equipment-selection-audit/EXAMPLES.md)说明报告拆分、公式差异和标准接入。随包backend图谱提供原公式/边界节点与标准事实；本项目计算台账和完整标准源文件仍由工程提供，示例不提供设计默认值。

### 12. 塔设备设计：chemical-tower-design

塔设备设计接收上游已明确的分离目标、物性压力、塔内负荷和内件范围，先冻结来源与设备身份，再调用设备参数链和适用标准方法。它不从一个 Aspen 塔结果直接跳到壳体尺寸，而是沿内件型式、各段控制工况、塔径、降液管及受液和无效面积、有效面积、开孔或填料几何，逐步检查压降、夹带、漏液和液泛。

水力学闭合后，继续组织塔板间距、塔高、接管与支承、质量材料和费用交接，并把压降影响返回工艺模型。负荷、塔径或几何改变时，沿依赖台账更新操作包络、负荷图、尺寸、规格书和报告；图中尺寸必须对应最新计算，最后独立核对高风险假设和几何闭合。F1 工具仅在相应浮阀负荷任务中检查来源绑定的给定曲线，不暗填经验边界或加载模型权重。正式内件、机械及厂家结论仍需同塔证据，不能把某塔的堰形、间距或经验范围当通用默认。

入口：[塔设备设计技能](../plugins/chemical-engineering-skills/skills/chemical-tower-design/SKILL.md)。执行设计时读取塔工作流，来源有冲突时读取证据路由；特定浮阀负荷边界的方法只在对应任务中使用。

相关文件：[塔设计工作流](../plugins/chemical-engineering-skills/skills/chemical-tower-design/references/tower_design_workflow.md)组织几何与水力学的依赖链；[证据路由](../plugins/chemical-engineering-skills/skills/chemical-tower-design/references/evidence_routing.md)处理来源选择。仅进行 F1 负荷边界任务时读[F1 接入说明](../plugins/chemical-engineering-skills/skills/chemical-tower-design/references/f1_load_performance_intake.md)并使用[f1_load_performance.py](../plugins/chemical-engineering-skills/skills/chemical-tower-design/scripts/f1_load_performance.py)，其输入曲线仍需来源支持。

### 13. EDR 评级与集成：aspen-edr-rating-delivery

EDR 模块先固定授权范围：单台任务检查指定设备，全流程评级任务盘点全部适用双流 HeatX；随后逐台固定冷热流股、负荷或温度目标、压力约束和允许几何材料。单流 Heater 不未经授权变成双流换热器。它先区分 Shortcut、非 EDR 的 Detailed、未通过或未绑定的 EDR 文件及真正执行状态，再决定补齐或修复哪一段，避免用一个标签替代真实软件证据。

实际评级使用同设备输入，通过既有 COM／文件方法运行并读取 EDR 消息和结果，先解决物性范围、出口状态、几何和振动等问题，再按正确 Rating 或 Design 角色绑定。复开模型后核对执行身份、输入路径、负荷、面积裕量、压降、速度与材料依据；热工问题不能被干净流程日志掩盖。评级结果交设备审查，集成模型交公共操作层完成精确文件及产品验证；携带 EDR 外部文件时还要核实实际归档成员与哈希。真实工作需合法 EDR 和同设备资料，热工评级、流程通过和厂家机械放行分开交回。

入口：[EDR 评级技能](../plugins/chemical-engineering-skills/skills/aspen-edr-rating-delivery/SKILL.md)。评级前阅读 EDR 校核要求，绑定前阅读软件卡片与文件角色说明；需要传递外部 EDR 文件时再阅读复合文件交付方法。

相关文件：[EDR 操作与卡片模式](../plugins/chemical-engineering-skills/skills/aspen-edr-rating-delivery/references/edr_com_card_patterns.md)用于接口和文件角色检查；[APWZ 复合文件交付](../plugins/chemical-engineering-skills/skills/aspen-edr-rating-delivery/references/apwz_compound_delivery.md)用于保存、携带和验证外部 EDR 依赖。实际 EDR 模型、物性曲线和评级结果需自行提供或生成。

### 14. SW6 数据传递：sw6-scripted-equipment-design

明确需要 SW6 字段传递、写后读回或计算书核对时，才进入这个窄模块。它从设备审查已明确的位号、结构、压力和直径基准、材料来源及 SW6 版本模块出发，确认当前任务有经过验证的字段映射与执行配置，再判断哪些数据可以安全序列化。另一版本或设备文件中的二进制偏移不能直接沿用，未确认的材料和几何保留为待验证配置。

安全字段传递后，使用当前用户提供的已验证本地运行器读回，逐行比较源值、换算、写入值和报告值；不一致先分辨映射、序列化、单位或依据冲突，再交回设备审查。管板、法兰、开孔补强和支座等结论须有同设备真实计算书或导出，不因少数字段写入成功就声称机械计算通过。本包提供工作合同，不包含通用 SW6 映射引擎、私人配置或商业软件；缺少它们时给具体依赖缺口，一般设备计算仍由相关模块继续。

入口：[SW6 数据传递技能](../plugins/chemical-engineering-skills/skills/sw6-scripted-equipment-design/SKILL.md)。先确认模块、结构、压力与直径基准，再使用与该版本对应的本地映射和计算流程。

相关文件：公开入口只提供工作合同与检查边界；专用 SW6 字段管线、映射配置和计算书属于外部资料或本地扩展，包内没有覆盖全部模块的一键机械设计器。

## 五、费用与技术文档

### 15. 非反应器设备费用：aspen-non-reactor-equipment-cost

这个模块接收确切模型身份、同案经济包和经济基准，先检查 Scenario1 是否属于当前模型且具有实际设备明细，再提取非反应器设备购置费。它保留原始行及被排除的反应器，按对应 Aspen 块汇总拆分塔等设备，并用项目级购置费交叉核对。购置费、安装费、总投资和公用工程运行费不能互换，明细与总表冲突时同时保留并要求复核。

随包包装器组织成本包查找、显式外部提取器调用和汇总；需要新生成经济包时，须先有使用者提供且适用于其安装版本的生成引擎，并在受保护模型上执行授权软件流程，不默认为本产品增加桌面依赖。成本目录或压缩包存在不证明尺寸和估价已经完成，缺设备锚点不能补零。交回内容包括原始与选定费用、覆盖及排除、未决项和来源基准。引擎、经济包、许可和批次资料按任务提供，本模块不处理反应器投资或环境影响评价。

入口：[非反应器设备费用技能](../plugins/chemical-engineering-skills/skills/aspen-non-reactor-equipment-cost/SKILL.md)。先检查 Scenario1 及设备明细是否有效，再解释价格字段；成本目录存在并不表示设备尺寸或估算已经完成。

相关文件：包内[单模型费用包装器](../plugins/chemical-engineering-skills/skills/aspen-non-reactor-equipment-cost/scripts/single_bkp_aepa_non_reactor_cost.py)组织同案成本包查找、外部提取器调用与结果汇总。使用者须显式提供提取引擎和锚点读取脚本；请求生成经济包时还需 GUI 引擎、适用软件及许可。成本包和批次清单不随包附带，包装器本身不包含费用计算引擎。

### 16. 项目成本方法构建：aspen-flowsheet-cost-skill-builder

新流程尚无可靠费用方法时，这个模块先只读盘点流程导出，按实际物理服务把软件块映射为设备，避免一块一设备或重复计入辅助项。随后逐项审定成本来源，记录容量变量、单位、适用范围、年份、币种、地区、材料与压力基准，重算原始锚点后才形成方法分配。不能因为某类设备缺资料，就借用另一类设备或目录最大价格。

映射和来源明确后，生成器把设备清单、尺寸算法、基价方法、基准调整及批量输入组织成项目专用 Skill 草稿，保留原代码模板。生成前检查显式数据目录中的必需 CSV，之后检验锚点、插值、范围边界、缺参和无效单位，并在可能时与同案经济包或独立来源比较。草稿、来源审查与工程就绪分别判定；比较层的代理估计和区间必须披露，不能假称严格费用齐全。完整成本数表及当前配方由使用者提供，最终将可重放方法与缺口交回项目经济比较。

入口：[成本方法构建技能](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-cost-skill-builder/SKILL.md)。先盘点设备职责，再审来源与方法；确定设备服务、容量变量和适用范围后，才生成项目专用批量方案。

相关文件：[source-discovery.md](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-cost-skill-builder/references/source-discovery.md)用于寻找并审定原始来源，[mapping-rules.md](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-cost-skill-builder/references/mapping-rules.md)用于软件块到实体设备的对应；[inventory_flowsheet.py](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-cost-skill-builder/scripts/inventory_flowsheet.py)生成清单，[audit_source_evidence.py](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-cost-skill-builder/scripts/audit_source_evidence.py)检查来源台账。生成专用方案前还应核对[generated-skill-contract.md](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-cost-skill-builder/references/generated-skill-contract.md)及[外部成本数据合同](../plugins/chemical-engineering-skills/skills/aspen-flowsheet-cost-skill-builder/references/external_cost_data.md)，通过显式数据目录提供所需的已审核 CSV。

### 17. 动力学技术说明：aspen-kinetics-documentation

动力学说明接收论文原式、参数表与页码、单位台账、实际 Aspen 卡片和 USER 源码，逐反应建立原式源值、源单位、目标基准、数值换算、输入位置及导出核对的链条。它先说明主动力学来源与补充闭合来源各解决什么，再围绕软件真正接收的参数写作，不把运行中由软件自行计算的瞬时速率示例混入输入参数说明。

涉及 USER 时，进一步核对反应计量和组分顺序、REAL／INT 位置、硬编码常数、运行时单位归一化，以及源文件、编译库和加载文件之间的关系。原生 POWERLAW 或 LHHW 只有完整保留源速率形式时才可采用，不能省略抑制项或改变浓度基准。链条不全的条目保留候选或缺口，交回流程建模补齐输入和软件证据。论文、子程序及真实运行依赖由当前任务提供，文档不补造常数，也不能凭 BKP 存在证明 USER 已执行。

入口：[动力学说明技能](../plugins/chemical-engineering-skills/skills/aspen-kinetics-documentation/SKILL.md)。说明围绕实际传入软件或子程序的参数展开；正式写入前，先完成源式、源单位、目标基准和导出验证的对应。

相关文件：本模块以入口正文中的反应条目、单位换算和 USER 映射要求为主，不附带通用动力学常数库或现成反应模型。源论文、子程序与编译产物由当前任务提供。

## 六、多工况工作与后置方法整理

### 18. 自适应流程模板：aspen-adaptive-generalization-loop

同类流程需要适应多种进料、规模或路线时，自适应模块先固定母模板、全部独立新鲜边界、产品目标、允许变量及代表工况覆盖。从守恒、自由度、空间时间、相态和库存寻找控制形式：闭式关系优先形成 Calculator，连续可调目标形成有边界的 Design Spec，响应不清先敏感性括区，只有确有物理分区或多根才增加分类和分组模板。不会按原料名字堆分支，也不因一个困难案例立即增加设备。

种子调试保留成功与失败，随后在不同工况检查产品、规模、残差和循环根。设计放大可在依据范围内调整几何或催化剂量，固定设备能力评价则保持几何并报告限制；模板改变后复跑受影响类，发布候选再覆盖冻结工况并执行真实模型复开验证。项目执行器、母模板和真实轨迹由当前工程提供。用户明确关闭当前版本后，可能的共性才进入中央整理：宏观原则与数值规律分层审查，放宽结果及派生内容只审计，没有可靠增量就不改 Skill；一次快跑或旧通过标签不证明一般规律。

入口：[自适应模板技能](../plugins/chemical-engineering-skills/skills/aspen-adaptive-generalization-loop/SKILL.md)。先从守恒、自由度、尺度和相态关系寻找控制形式，再按覆盖要求验证。项目 runner、母模板、历史轨迹及事件库属于外部资料或本地扩展。

相关文件：准备在任务关闭后整理可复用方法时，读取中央[后置进化流程](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/EVOLUTION_LOOP.md)；真正提交候选时再读[候选数据合同](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/evolution_review_contract.md)。[evaluate_learning_eligibility.py](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/scripts/evaluate_learning_eligibility.py)检查来源资格，[assess_evolution_candidate.py](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/scripts/assess_evolution_candidate.py)检查基线、事实观察与回退依据，均不自动发布规则。

### 19. 子代理协作：subagent-dispatch

主代理先把下一步工作分成可独立取得的事实和必须统筹判断的事项。对互不阻塞的读取、定向检索、批准脚本执行或独立核对，分派明确目标、文件范围、返回字段与停止条件；修改任务还要限定互不重叠的写入区域。后续同类工作优先交给已有合适代理，避免重复开工和同时修改同一文件。

子代理返回路径、行号、数值、状态和缺口，不自动成为工程权威。主代理核对范围、失败和来源，再将事实接入方案选择、验收和最终交付，紧密耦合的取舍仍自己承担。完成后释放不再需要的代理与资源，只清理确认属于本任务且不再使用的临时内容，不动用户成果和在用证据。本 Skill 使用宿主已有协作能力，不包含独立代理服务，也不保证某个工具名称可用。

入口：[子代理协作技能](../plugins/chemical-engineering-skills/skills/subagent-dispatch/SKILL.md)。分派前确认任务可独立进行，写入范围互不冲突；后续工作优先复用已有适合的代理。

相关文件：入口正文中的任务合同、并发和整合要求即为本模块的主要内容。它不包含独立代理服务端，也不保证特定宿主提供某个工具名称。

## 七、各模块共用的运行层

在确定源路线、取得简化骨架负荷、严化单元岛、接回工段、实质改变工况或准备交付时，主流程按[设计阶段调用规则](../plugins/chemical-engineering-skills/skills/chemical-engineering-expert/references/DESIGN_STAGE_ROUTING.md)执行实际知识与设备检查。对应阶段是 `source`、`scaffold`、`island`、`reconnect`、`change` 和 `delivery`：尚未有工况的源路线阶段先检索系统原则并发现设备能力，已有工况的阶段再用当前设备清单、单位、来源和案例身份调用计算，必要时进入原反馈与复算核对。只查定义、换单位、做组分模板或文字修改，不因此编造完整设备清单。

[统一入口](../tools/expert_cli.py)的 `design_stage` 操作由[阶段调用实现](../tools/design_stage.py)衔接既有查询、设备和反馈程序；字段先通过 `--schema design-stage` 读取，支持 MCP 的宿主也可调用同一实现的 `design_stage_check`。回执记录实际请求、响应及身份，但主代理仍要读懂命中节点、判断方法适用性和清单覆盖。`MODULE_CHECKS_EXECUTED` 只说明所列检查已执行，`ACTION_REQUIRED` 表示还需行动，两者都不是工程通过；这个入口不自动运行 Aspen，也不代替专业模块修改模型和完成精确文件验收。

19个专业入口共用包内的知识、设备、压力和反馈工具，不分别安装一套后端。
[统一命令入口](../tools/expert_cli.py)接收自然语言检索或结构化计算请求；
[能力与字段说明](../tools/product_contract.py)从实际后台返回可用操作及原协议，
并根据安装记录找到Skill位置。[驻留设备调用层](../tools/equipment_gateway.py)
复用同一个后台进程，仍逐次检查冻结身份和每份请求响应的对应关系。

需要从计算回到工艺时，使用[流程反馈接口说明](../plugins/chemical-engineering-skills/skills/equipment-design-app/references/process_feedback_bridge.md)
和[完整合成示例生成器](../examples/prepare_feedback_case.py)。示例展示从来源、
单位和限值到计算、调整候选和待复算对象的链条，不是实际工程的默认参数。

知识新增和知识检索分开。[知识维护说明](../knowledge/MAINTENANCE.md)规定来源
登记、逐节点审核、候选构建及验证。普通资料增补按每个节点的来源、定位、哈希、许可及独立审核处理，不要求伪造任务关闭；任务经验提炼才额外执行中央关闭、谱系和质量门。构建结果位于独立候选目录，未准入内容保留待审且不进入默认向量，不原地污染已发布库。[owner定位](../knowledge/OWNER_ROUTES.md)
把每个图谱的错误和新知识入口接到唯一专业负责人，不复制一组独立进化规则。
CLI和[MCP接口](../tools/expert_mcp.py)调用同一实现；MCP只是宿主调用方式，不改变
工程判断、数据权威或验收标准。

## 怎样组合这些模块

### 查数、运行关系和调参的共同入口

建模、塔优化、热泵、自适应模板、故障修复和公共操作层共用
[内置工具规则](../plugins/chemical-engineering-skills/skills/aspen-document-driven-flowsheet/references/aspen_builtin_solve_fit_tools.md)，
不各写一套相反的选择标准。专家层在问题出现时触发分类，流程层安排时机，
专项模块决定真实自由度和约束，操作层落实为本版 Aspen 对象并取回证据。

读已有数值先走只读路径；必须随运行更新的明确关系才放进 Calculator。
Sensitivity 找响应和区间，Design Spec/Vary 闭合目标，Optimization 在约束
下找更优设计。当前工况发生变化后，内层目标、设备和上下游检查随之更新。
程序接口 [aspen_tool_router.py](../tools/aspen_tool_router.py)只返回方法和待办，
不宣称原生软件已经执行；它由 CLI 的 `solve_route` 和 MCP 的
`aspen_solve_route` 共用，独立查询不要求全流程设备清单。

### 无界面后台的交接过程

模型先从统一查询入口取得适用的原理、方法或设备标准事实，再把当前工况交给原设备程序。该程序计算所有可以闭合的量，给出型式、规格层级及缺口；反馈层随后检查是否存在可归因的真实能力限制。只有条件满足时才提出换热器串联、压缩分级或塔并联的候选，并列出必须重算的流股、压力、能量与产品关系。建模技能在当前授权下实施改动，重新运行实际模型，再把新导出交回选型和各专业校核。工具不会用外部计算替代Aspen原生求解。

逐步输入、公式、反馈失效条件和实例见[后台运行与计算说明](后台运行与计算说明.md)。原知识、标准表和代码的逐文件来源分别保存在各模块manifest中；维护源码不参与默认检索，也不因随包保留就自动获得新项目运行权限。

一个完整流程任务通常先由化工专家明确方法与系统约束，再由文档或分段模块组织路线；分离、热泵和设备模块完成各自职责，公共操作模块执行软件动作。设备限制或工艺改动反馈后，应更新相关流股、循环、热功负荷、产品和经济基准，再检查精确交付文件。

短问题不必走完整链条。只查机理时可以不启动软件；只读已有数据时也不应被误写成整厂验收。相应阶段需要什么证据，就检查什么证据，并清楚说明尚未证明的部分。

任务结束后的方法整理同样保持这一边界：来源资格、候选比对、独立验证和人工批准是不同步骤。用户关闭任务不等于自动批准所有经验；任何允许降低要求的当前任务及其派生内容，都不能成为共享严格规则的依据。
